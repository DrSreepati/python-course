## 1. What conditional logic is

Conditional logic means taking a different action based on the result of a condition. In business, a decision may depend on order amount, customer type or payment status.

```python
order_amount = 12000

if order_amount >= 10000:
    print("Discount eligible")
```

**Output**

```text
Discount eligible
```

Here `order_amount >= 10000` is true, so the indented `print()` runs. The colon `:` after `if` is required.

Important lines:

- `if` starts the condition.
- `>=` compares with the boundary included.
- The indented line belongs to the condition's block.

## 2. A simple `if`

An `if` block runs when its condition is true. When the condition is false, the block is skipped.

```python
profit = 2500

if profit > 0:
    print("The sale made a profit")
```

**Output**

```text
The sale made a profit
```

Now with a loss:

```python
profit = -500

if profit > 0:
    print("The sale made a profit")

print("Report checked")
```

**Output**

```text
Report checked
```

`profit > 0` is false, so the first print does not run. The report check outside the indentation runs every time.

## 3. Boolean results from comparisons

Looking at a comparison separately can make a conditional rule easier to understand.

```python
balance = 32000

is_large_balance = balance >= 30000
print(is_large_balance)

if is_large_balance:
    print("Review customer balance")
```

**Output**

```text
True
Review customer balance
```

`is_large_balance` is a Boolean variable. A meaningful Boolean name makes the rule easier to read than a complicated expression alone.

## 4. The indentation block

In Python, indentation shows which lines belong to an `if` block. Use four spaces as the usual indentation.

```python
order_amount = 12000

if order_amount >= 10000:
    discount_rate = 0.05
    print("Discount rate:", discount_rate)

print("Order processed")
```

**Output**

```text
Discount rate: 0.05
Order processed
```

Both indented lines belong to the same block. `Order processed` is outside the indentation, so it runs whether the condition is true or false.

Wrong indentation:

```python
# if order_amount >= 10000:
# print("Discount eligible")
```

If a block line is not indented after `if`, Python may raise `IndentationError`. Keep lines in the same block at the same indentation level.

## 5. Two conditions with `and`

With `and`, both conditions must be true.

```python
order_amount = 12000
customer_balance = 50000

if order_amount >= 10000 and customer_balance >= 30000:
    print("Approve discount review")
```

**Output**

```text
Approve discount review
```

Both the order threshold and the customer-balance condition pass. If one condition is false, the block does not run.

```python
order_amount = 12000
customer_balance = 18000

if order_amount >= 10000 and customer_balance >= 30000:
    print("Approve discount review")

print("Checked")
```

**Output**

```text
Checked
```

## 6. Thresholds and boundaries

The boundary is important in a business rule. If the rule says â€œorders of 10,000 or more receive a discount,â€ use `>=`.

```python
order_amount = 10000

if order_amount >= 10000:
    print("Boundary order qualifies")
```

**Output**

```text
Boundary order qualifies
```

Using `>` would exclude 10,000:

```python
order_amount = 10000

if order_amount > 10000:
    print("Discount eligible")
```

**Output**

```text
```

Read the requirement first: use `>` for â€œgreater thanâ€ and `>=` for â€œat least.â€

## 7. A customer discount decision

Now apply the order-amount and customer-balance rules together.

```python
customer_name = "Rahim Traders"
order_amount = 12000
customer_balance = 50000

if order_amount >= 10000 and customer_balance >= 30000:
    print(f"{customer_name}: discount review approved")
```

**Output**

```text
Rahim Traders: discount review approved
```

Because of `and`, the approval message appears only when both conditions pass. This `if` block reports the decision; the next subtopic will use `else` for the false case.

## 8. A payment-status check

When an outstanding balance is positive, the customer may need payment follow-up.

```python
customer_name = "Karim Store"
outstanding = 32000

if outstanding > 0 and outstanding >= 30000:
    print(f"{customer_name}: payment follow-up needed")
```

**Output**

```text
Karim Store: payment follow-up needed
```

The two conditions make the balance rule explicit. `outstanding >= 30000` alone could be enough, but this example shows how multiple policy rules can be written with `and`. In real code, avoid duplicate conditions and keep the rule readable.

## 9. Code outside the condition

It is important to know which lines are inside the conditional block and which lines always run.

```python
profit = -800

if profit > 0:
    print("Profit found")

print("Daily report saved")
```

**Output**

```text
Daily report saved
```

The profit message is skipped, but the report-saving message runs because it is outside the `if` block.

## 10. A complete business decision workflow

Store each part of a business rule in a named variable, then make the decision with `if`.

```python
customer_name = "Jahid Enterprise"
order_amount = 13200
customer_balance = 71000

large_order = order_amount >= 10000
reliable_balance = customer_balance >= 30000

if large_order and reliable_balance:
    print(f"{customer_name}: approve discount review")
    print("Reason: large order and balance threshold passed")

print("Decision recorded")
```

**Output**

```text
Jahid Enterprise: approve discount review
Reason: large order and balance threshold passed
Decision recorded
```

The workflow is:

- store the business values;
- store each rule's Boolean result in a named variable;
- test both results with `and`;
- perform the approval action in the indented block;
- record the decision outside the block.

## Troubleshooting

### Problem 1: `IndentationError` appears

- **What happens:** Python reports an indentation problem in the block.
- **Likely cause:** The line after `if` is not indented, or spaces differ within one block.
- **Steps:** Use four spaces for each block line and do not mix tabs and spaces.
- **Prevention:** Use VS Code's automatic indentation.

### Problem 2: The message does not appear even though the condition seems true

- **What happens:** The expected approval message is not printed.
- **Likely cause:** The comparison boundary is wrong, or the second `and` condition is false.
- **Steps:** Print each comparison as a separate Boolean variable.
- **Prevention:** Use named rules such as `large_order` and `reliable_balance`.

### Problem 3: The exact threshold is excluded

- **What happens:** An order of 10,000 does not receive a discount.
- **Likely cause:** `>` was written instead of `>=`.
- **Steps:** Check whether the requirement says â€œat leastâ€ or â€œmore than.â€
- **Prevention:** Test the boundary value directly.

### Problem 4: The whole block does not run after `and`

- **What happens:** One true condition does not produce the action.
- **Likely cause:** The other condition is false; `and` requires every condition to pass.
- **Steps:** Print the result of both conditions separately.
- **Prevention:** Write each business requirement first as a named Boolean rule.

## Common Misconceptions

1. **Wrong:** The indented line runs even when `if` is false. -> **Correct:** The whole block is skipped when false.
2. **Wrong:** `and` means any one condition can be true. -> **Correct:** Every condition must be true.
3. **Wrong:** Indentation is only for visual style. -> **Correct:** Indentation defines Python's block structure.
4. **Wrong:** `>` and `>=` are the same. -> **Correct:** `>=` includes the exact threshold value.
5. **Wrong:** All code after `if` is conditional. -> **Correct:** Only the indented block is conditional; outside lines normally run every time.

## Quiz

### 1. When does an `if` block run?

a. When the condition is `True`
b. When the condition is `False`
c. Never

**Answer: a.** An indented block executes when the condition is true.

### 2. What is required with `and`?

a. One condition must be true.
b. Every condition must be true.
c. No condition is required.

**Answer: b.** `and` tests all conditions together.

### 3. Why is a colon used after `if`?

a. To mark the start of the block.
b. To delete a variable.
c. To create a number.

**Answer: a.** The indented suite follows the colon.

### 4. Which operator means â€œ10,000 or moreâ€?

a. `>`
b. `>=`
c. `<`

**Answer: b.** `>=` includes the threshold value and larger values.

### 5. Which line is inside an `if` block?

a. A line with the same indentation.
b. An indented line.
c. The final line in the file.

**Answer: b.** Indentation shows block membership.

### 6. What does a line outside the block do when the condition is false?

a. It normally runs.
b. It is always deleted.
c. It raises a syntax error.

**Answer: a.** An outside line is not part of the conditional block.

### 7. What is a good way to express two business rules clearly?

a. Hide every expression on one line.
b. Use meaningful Boolean variables.
c. Remove variable names.

**Answer: b.** Named rules make the logic readable.

## Key Idea

`if` runs an action for a true condition, `and` checks whether all conditions are true, and indentation defines the block boundary. Read the exact business requirement before choosing `>` or `>=` for a threshold.

**Rhyme 1:** If the rule is true, let the block run,
**Rhyme 2:** Keep indentation right and decisions become fun.
