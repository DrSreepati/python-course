## 1. Why money data matters

One tiny currency error can grow across a large report. Keep price, quantity, and amount clear.

```python
unit_price = 250.50
quantity = 4
amount = unit_price * quantity

print(amount)
```

**Output**

```text
1002.0
```

`unit_price` is the price per item. `quantity` is four items. Their product is the amount.

## 2. Prices with `float`

`float` stores decimal numbers. It is useful for simple learning examples with prices and rates.

```python
unit_price = float("250.50")
vat_rate = float("7.5")

print(unit_price)
print(vat_rate)
print(type(unit_price))
```

**Output**

```text
250.5
7.5
<class 'float'>
```

`float()` changed text into decimal numbers. Python may omit an unnecessary final zero when printing.

## 3. The `0.1 + 0.2` surprise

Computers store many decimal values as approximate binary fractions. The result may differ from human display expectations.

```python
result = 0.1 + 0.2
print(result)
```

**Output**

```text
0.30000000000000004
```

This is not faulty arithmetic. The binary representations of `0.1` and `0.2` are approximate, so a small representation error appears.

## 4. `repr()` and `print()`

`repr()` helps show a value’s detailed representation. `print()` is for normal display.

```python
result = 0.1 + 0.2
print(result)
print(repr(result))
```

**Output**

```text
0.30000000000000004
0.30000000000000004
```

Both lines match here. The float result contains extra digits, although a business report may show only cents.

## 5. Displaying with `round()`

`round()` rounds a value to a chosen number of decimal places. It is useful for display and simple presentation.

```python
result = 0.1 + 0.2
display_value = round(result, 2)

print(result)
print(display_value)
```

**Output**

```text
0.30000000000000004
0.3
```

The first line shows the raw float. The second shows the value rounded to two decimal places.

## 6. Float amounts

Multiplying quantity by unit price gives an amount. Reports often display two decimal places.

```python
unit_price = 19.99
quantity = 3
amount = unit_price * quantity

print(amount)
print(round(amount, 2))
```

**Output**

```text
59.97
59.97
```

The raw result looks clean here. Still, `round(amount, 2)` makes the report display rule explicit.

## 7. Equality risks

Two floats may look equal but fail an exact equality test.

```python
calculated = 0.1 + 0.2
expected = 0.3

print(calculated == expected)
print(round(calculated, 2) == expected)
```

**Output**

```text
False
True
```

The first test compares raw representations. The second compares to two decimal places, so it is true here.

## 8. Storing smallest units as integers

When the smallest currency unit is cents or paisa, store an amount as an integer unit. This avoids this float problem.

```python
price_paisa = 1999
quantity = 3
amount_paisa = price_paisa * quantity

print(amount_paisa)
print(amount_paisa / 100)
```

**Output**

```text
5997
59.97
```

The first calculation uses whole paisa. The final division is for display, so storage and display rules must remain separate.

## 9. Introducing decimal-based values

Python’s `decimal.Decimal` stores decimal-style values for financial work. We only introduce it today.

```python
from decimal import Decimal

result = Decimal("0.1") + Decimal("0.2")
print(result)
```

**Output**

```text
0.3
```

The constructor receives strings. This makes the decimal intent clear, and the sum is `0.3`.

## 10. Choosing a business rule

Projects need a clear money rule. Simple examples may use `float` and `round()`. Financial systems may use integer units or `Decimal`.

```python
from decimal import Decimal

unit_price = Decimal("19.99")
quantity = 3
amount = unit_price * quantity

print(amount)
```

**Output**

```text
59.97
```

The price is a `Decimal`. The quantity is an integer. Their product is an exact decimal-style amount.

## Troubleshooting

### Problem 1: `0.1 + 0.2` looks strange

- **What is happening:** Python shows `0.30000000000000004`.
- **Most likely cause:** A float stores the decimal approximately in binary.
- **Step-by-step fix:** 1. Print the raw result. 2. Round it for display. 3. Choose a money storage rule. 4. Use integer units or `Decimal` when needed.
- **How to prevent it:** Do not show raw float results as final money reports.

### Problem 2: Two price outputs look different

- **What is happening:** Raw and rounded amounts do not match visually.
- **Most likely cause:** Calculation and display values were treated as one thing.
- **Step-by-step fix:** 1. Keep the raw value. 2. Round for the report. 3. Label storage and display values clearly.
- **How to prevent it:** Use names such as `raw_amount` and `display_amount`.

### Problem 3: Float equality is false

- **What is happening:** `0.1 + 0.2 == 0.3` is false.
- **Most likely cause:** A tiny binary representation difference exists.
- **Step-by-step fix:** 1. Print raw values. 2. Set the required precision. 3. Compare rounded values or use `Decimal`.
- **How to prevent it:** Do not use exact equality for money floats.

### Problem 4: The money storage rule is unclear

- **What is happening:** The team cannot choose float, integer units, or `Decimal`.
- **Most likely cause:** Currency and precision policies were not written.
- **Step-by-step fix:** 1. Define the smallest currency unit. 2. Choose storage. 3. Define display. 4. Test sample calculations.
- **How to prevent it:** Document the money policy at project start.

## Common Misconceptions

1. **Wrong claim:** `0.1 + 0.2` is always exactly `0.3`. **Truth:** Float representation may create a tiny raw difference.
2. **Wrong claim:** `round()` always makes internal float storage exact money. **Truth:** It rounds a result. Storage is a separate policy.
3. **Wrong claim:** Seeing `59.97` proves the internal value is exact. **Truth:** Display format and internal representation can differ.
4. **Wrong claim:** `float` is best for every money field. **Truth:** Integer units or `Decimal` may suit financial rules better.
5. **Wrong claim:** Float equality is safe for every business comparison. **Truth:** Choose the required precision first.

### Exercise 5: Rafiq bhai’s debugging bug

Rafiq bhai used float equality to test the boss’s expected amount:

```python
calculated = 0.1 + 0.2
if calculated == 0.3:
    print("Amount matches")
else:
    print("Amount does not match")
```

**Wrong output**

```text
Amount does not match
```

The boss said, “Why did two small amounts produce a mismatch?”

**Solution**

Raw float equality sees a tiny representation difference. For this simple display comparison, round to two decimal places first.

```python
calculated = 0.1 + 0.2
if round(calculated, 2) == 0.3:
    print("Amount matches")
else:
    print("Amount does not match")
```

**Correct output**

```text
Amount matches
```

One-line lesson: set the required precision before comparing money floats.
