## 1. Business data names

In a business report, `quantity` means how many items. `unit_price` means the price of one item. `amount` means the total price. Six items at 250 taka each cost 1500 taka.

```python
quantity = 6
unit_price = 250
amount = quantity * unit_price

print(quantity)    # Expected: 6
print(unit_price)  # Expected: 250
print(amount)      # Expected: 1500
```

The variables hold the inputs. The multiplication produces the amount. The output shows all three values.

## 2. Quantity and unit price

A whole-number quantity can use `int`. A price may contain decimals, so `float` is common. Financial systems may also use Decimal or integer smallest units, as seen in 2.6.

```python
quantity = 4
unit_price = 125.50

print(type(quantity))    # Expected: <class 'int'>
print(type(unit_price))  # Expected: <class 'float'>
```

`type()` reports a value's type. `4` is an integer. `125.50` is a float.

## 3. Amount calculation

The formula is `amount = quantity * unit_price`. Reversing a business formula may run without an error, but it can produce a wrong result.

```python
quantity = 8
unit_price = 175.00
amount = quantity * unit_price

print(f"Amount: {amount:.2f} taka")  # Expected: Amount: 1400.00 taka
```

The `:.2f` format shows two decimal places. It is display formatting, not a complete storage rule.

## 4. Percentage and rate

A percentage means a number out of 100. For calculation, `15%` becomes `15 / 100`, or `0.15`.

```python
discount_percentage = 15
discount_rate = discount_percentage / 100

print(discount_rate)  # Expected: 0.15
```

The first variable matches a report. The second variable is ready for calculation.

## 5. Percentage calculation

Multiply the amount by the rate to get discount. Subtract the discount to get the net amount.

```python
amount = 2000
discount_percentage = 15
discount_amount = amount * discount_percentage / 100
net_amount = amount - discount_amount

print(discount_amount)  # Expected: 300.0
print(net_amount)       # Expected: 1700.0
```

`2000 * 15 / 100` is 300. Then `2000 - 300` is 1700.

## 6. Why dates are different

`"2026-11-01"` looks like a date. Inside quotes, Python sees a string. String operations are not a safe replacement for date arithmetic. We will learn date arithmetic in Chapter 11.3.

```python
report_date_text = "2026-11-01"
print(report_date_text)       # Expected: 2026-11-01
print(type(report_date_text)) # Expected: <class 'str'>
```

Text is useful for display and input. Date calculations later need `datetime.date`.

## 7. Choosing types

A business record contains different types. Codes, names and display dates can be strings. Quantity is an integer. A percentage or amount is numeric. A paid flag is Boolean.

```python
invoice_no = "INV-2024-007"
customer = "Rahim Traders"
quantity = 3
unit_price = 450.00
paid = False

print(type(invoice_no))  # Expected: <class 'str'>
print(type(quantity))    # Expected: <class 'int'>
print(type(unit_price))  # Expected: <class 'float'>
print(type(paid))        # Expected: <class 'bool'>
```

Each value has a type that matches its job.

## 8. First validation idea

Validation means checking whether input follows a business rule. A zero or negative quantity may be suspicious for a wholesale sale.

```python
quantity = 0

if quantity > 0:
    print("Quantity is usable")  # Expected: this branch does not run
else:
    print("Check the quantity")  # Expected: Check the quantity
```

Zero is not greater than zero, so the second message appears.

## 9. A small sales record

A sale can have an invoice, customer, quantity, unit price and date. We use separate variables today. Dictionaries come later.

```python
invoice_no = "INV-2024-007"
customer = "Rahim Traders"
quantity = 5
unit_price = 320.00
amount = quantity * unit_price

print(invoice_no)  # Expected: INV-2024-007
print(customer)    # Expected: Rahim Traders
print(amount)      # Expected: 1600.0
```

The first two values identify the sale. The next two feed the calculation. The last is calculated output.

## 10. Business rules and care

If a report says 15, it may mean 15%. A calculation needs 0.15. A date can be read as text, but date calculations need another type. Display format and internal number are not the same.

```python
quantity = 6
unit_price = 250
percentage = 10
amount = quantity * unit_price
discount = amount * percentage / 100

print(f"Gross: {amount:.2f}")        # Expected: Gross: 1500.00
print(f"Discount: {discount:.2f}")  # Expected: Discount: 150.00
```

The code calculates gross amount first. It then calculates the percentage discount. Formatting only changes the display.

## Synthesis table

| Business value | Meaning | Common type | Example |
|---|---|---|---|
| quantity | number of items | `int` | `6` |
| unit price | price of one item | `float` or Decimal | `250.50` |
| amount | total price | float or Decimal | `quantity * unit_price` |
| percentage | number per 100 | `int` or float | `15` |
| rate | calculation form | `float` | `0.15` |
| invoice code | identifier | `str` | `"INV-2024-007"` |

## Troubleshooting

### Problem 1: The amount joins text

- What is happening: `"6" + "250"` joins text instead of calculating.
- Most likely cause: an `input()` value was not cast.
- Fix: inspect `type()`, use `int()` or `float()`, then calculate.
- Prevention: cast input as soon as you read it.

### Problem 2: The discount is fifteen times too large

- What is happening: 15 was used as the rate.
- Most likely cause: percentage and rate were confused.
- Fix: use `amount * percentage / 100`, or set `rate = percentage / 100`.
- Prevention: use names such as `discount_percentage` and `discount_rate`.

### Problem 3: A date cannot be added to

- What is happening: adding a number to date text causes an error.
- Most likely cause: the date is still a `str`.
- Fix: inspect the type, then learn `datetime.date`.
- Prevention: keep display text separate from date calculations.

### Problem 4: The amount has too many decimal places

- What is happening: a float display such as `1600.0` appears.
- Most likely cause: display formatting was not applied, or float limits are visible.
- Fix: use `:.2f` for display and choose a financial storage rule.
- Prevention: separate display, calculation and storage decisions.

## Common Misconceptions

1. **Wrong:** all business data should be strings → **Truth:** codes and names are strings, but quantities need numbers.
2. **Wrong:** 15 is always a 15% rate → **Truth:** the rate is `0.15`.
3. **Wrong:** `"2026-11-01"` is already a date → **Truth:** it is a string.
4. **Wrong:** `:.2f` makes money financially safe → **Truth:** it only formats display.
5. **Wrong:** type does not matter before calculation → **Truth:** checking type prevents mistakes.
