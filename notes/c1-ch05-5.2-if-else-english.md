## 1. What a two-path decision is

When one action is needed if a condition is true and another action if it is false, use a two-path decision. Python uses `if-else` for this.

```python
order_amount = 8000

if order_amount >= 10000:
    print("Discount eligible")
else:
    print("No discount")
```

**Output**

```text
No discount
```

The order amount is below the threshold, so the `else` block runs. Only one of the `if` and `else` blocks runs in this execution.

## 2. `if-else` syntax

The true block follows the `if` condition, and the false block follows `else`. The action lines in both blocks are indented.

```python
profit = 2500

if profit > 0:
    print("Profit")
else:
    print("Loss or break-even")
```

**Output**

```text
Profit
```

`profit > 0` is true, so the first block runs. The `else` block does not run in the same execution.

Break-even value:

```python
profit = 0

if profit > 0:
    print("Profit")
else:
    print("Loss or break-even")
```

**Output**

```text
Loss or break-even
```

Here `0 > 0` is false, so `else` runs. When a separate category is needed later, use `elif`.

## 3. Receiving or not receiving a discount

Show a discount when the order reaches the threshold, and an explanation when it does not.

```python
customer_name = "Rahim Traders"
order_amount = 9500

if order_amount >= 10000:
    print(f"{customer_name}: discount approved")
else:
    print(f"{customer_name}: minimum order not reached")
```

**Output**

```text
Rahim Traders: minimum order not reached
```

The customer's order is not `10000`, so the false path is reported clearly. Using `else` prevents an input from becoming a silent case.

## 4. Indentation of the `else` block

The `else` keyword must align with `if`. Its action must be indented by four spaces.

```python
order_amount = 12000

if order_amount >= 10000:
    message = "Discount approved"
else:
    message = "No discount"

print(message)
```

**Output**

```text
Discount approved
```

`message` is created in both paths and printed outside the blocks. Assigning the same output variable in both branches makes common reporting easier.

Wrong structure:

```python
# if order_amount >= 10000:
#     print("Discount approved")
#     else:
#         print("No discount")
```

If `else` is not aligned with `if`, Python raises a syntax or indentation error.

## 5. `if-elif-else` syntax

Use `elif` when there are more than two categories. Python checks conditions from top to bottom; after the first true branch runs, the remaining branches are skipped.

```python
outstanding = 0

if outstanding == 0:
    print("Paid")
elif outstanding > 0:
    print("Outstanding")
else:
    print("Credit balance")
```

**Output**

```text
Paid
```

The first condition is true, so Python does not take action from `elif` or `else`.

## 6. Threshold order

When several thresholds exist, put the more specific or larger threshold first. Otherwise, a smaller condition may become true and block the larger category.

```python
order_amount = 15000

if order_amount >= 15000:
    print("Gold order")
elif order_amount >= 10000:
    print("Silver order")
else:
    print("Standard order")
```

**Output**

```text
Gold order
```

Wrong order:

```python
order_amount = 15000

if order_amount >= 10000:
    print("Silver order")
elif order_amount >= 15000:
    print("Gold order")
else:
    print("Standard order")
```

**Output**

```text
Silver order
```

The code has no error, but the business category is wrong. This is a silent logic bug.

## 7. Payment-status classification

Classify a customer's payment status into three groups using the outstanding balance.

```python
customer_name = "Karim Store"
outstanding = 32000

if outstanding == 0:
    status = "Paid"
elif outstanding >= 30000:
    status = "High outstanding"
else:
    status = "Small outstanding"

print(f"{customer_name}: {status}")
```

**Output**

```text
Karim Store: High outstanding
```

`outstanding == 0` comes first because a paid customer has a separate meaning. Then the high outstanding category is checked, and the final branch covers the remaining positive balance.

## 8. Profit/loss classification

Profit can be positive, zero or negative, producing three categories.

```python
profit = 0

if profit > 0:
    label = "Profit"
elif profit < 0:
    label = "Loss"
else:
    label = "Break-even"

print(label)
```

**Output**

```text
Break-even
```

Here `elif` separates negative values and `else` acts as the fallback for zero.

## 9. A fallback `else`

`else` handles values that did not match any earlier condition. It creates a default outcome for the input.

```python
payment_method = "cash"

if payment_method == "bank":
    print("Bank payment")
elif payment_method == "card":
    print("Card payment")
else:
    print("Other payment method")
```

**Output**

```text
Other payment method
```

`cash` is neither bank nor card, so the fallback message appears. A specific `elif` can be added later for a new payment method.

## 10. A complete business decision workflow

Now create a discount category from customer, order and balance information.

```python
customer_name = "Jahid Enterprise"
order_amount = 13200
customer_balance = 71000

if order_amount >= 15000 and customer_balance >= 30000:
    decision = "Gold discount review"
elif order_amount >= 10000 and customer_balance >= 30000:
    decision = "Standard discount review"
else:
    decision = "No discount review"

print(f"{customer_name}: {decision}")
```

**Output**

```text
Jahid Enterprise: Standard discount review
```

The workflow is:

- store the order amount and balance;
- check the larger category first;
- use a medium threshold for the second category;
- use `else` as the fallback when no rule passes;
- report the final decision with the customer name.

## Synthesis table

| Concept | Example | Meaning |
|---|---|---|
| `if-else` | `if paid: ... else: ...` | two true/false paths |
| `elif` | `elif profit < 0:` | checks the next condition |
| `else` | `else: label = "Other"` | fallback when no earlier condition matches |
| First match | top to bottom | stops at the first true branch |
| Threshold order | larger threshold first | prevents wrong categories |
| Zero case | `amount == 0` | a separate business meaning |
| Mutually exclusive | one branch | one path runs per execution |
| Final report | `print(decision)` | communicates the decision |

## Troubleshooting

### Problem 1: A syntax error appears near `else`

- **What happens:** Python does not accept the `else` statement.
- **Likely cause:** The colon is missing before the block, or `else` is not aligned with `if`.
- **Steps:** Write `if condition:` and `else:` at the same indentation level.
- **Prevention:** Follow the editor's block indentation.

### Problem 2: The first category is always printed

- **What happens:** A Gold order is labelled Silver.
- **Likely cause:** The smaller threshold was written first.
- **Steps:** Move the larger or more specific threshold branch above it.
- **Prevention:** Test every category with boundary values.

### Problem 3: A variable is unavailable after the chain

- **What happens:** Printing the variable later raises `NameError`.
- **Likely cause:** The variable was assigned in only one branch.
- **Steps:** Assign the same output variable in every branch.
- **Prevention:** Keep a default outcome for the common report variable.

### Problem 4: A zero value goes to the wrong category

- **What happens:** `0` is labelled as a loss or outstanding amount.
- **Likely cause:** There is no separate rule for zero.
- **Steps:** Write the `amount == 0` rule first when the business meaning requires it.
- **Prevention:** Test positive, negative and zero boundaries.

## Common Misconceptions

1. **Wrong:** Both branches of `if-else` run. -> **Correct:** Only one branch runs according to the condition.
2. **Wrong:** `elif` tests every condition. -> **Correct:** The chain skips the remaining branches after the first true branch.
3. **Wrong:** `else` has its own condition. -> **Correct:** `else` is an unconditional fallback.
4. **Wrong:** Threshold order does not matter. -> **Correct:** The first match determines the final category.
5. **Wrong:** Zero is always like a positive or negative value. -> **Correct:** Zero may have a separate business meaning.

## Key Idea

`if-else` handles two true/false paths, while `if-elif-else` chooses the first matching path among several categories. Correct condition order, boundaries and fallback behavior make business decisions reliable.

**Rhyme 1:** If is true, else takes the other way,
**Rhyme 2:** Put the bigger rule first for a correct category.
