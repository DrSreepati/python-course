## 6. Why duplicate invoices matter

If an invoice is uploaded twice, sales totals can be wrong. A set gives the unique count. To find the repeated names, scan the list with a `seen` set.

```python
invoices = ["INV-007", "INV-008", "INV-007", "INV-009", "INV-008"]
unique_invoices = set(invoices)

print("Total rows:", len(invoices))
print("Unique invoices:", len(unique_invoices))
print("Unique list:", sorted(unique_invoices))
```

**Output**

```text
Total rows: 5
Unique invoices: 3
Unique list: ['INV-007', 'INV-008', 'INV-009']
```

The list length counts every row. The set length counts unique invoices.

## 7. Building a duplicate report

A set alone loses duplicate history. Put the first occurrence in `seen`. When it appears again, add it to `duplicates`.

```python
invoices = ["INV-007", "INV-008", "INV-007", "INV-009", "INV-008"]
seen = set()
duplicates = []

for invoice in invoices:
    if invoice in seen:
        if invoice not in duplicates:
            duplicates.append(invoice)
    else:
        seen.add(invoice)

print("Duplicates:", duplicates)
```

**Output**

```text
Duplicates: ['INV-007', 'INV-008']
```

`seen` performs membership checks. `duplicates` keeps discovery order.

## 8. Unique customer IDs

One customer may have many invoices. Use a set when the customer register needs each ID once.

```python
customer_ids = ["C-1023", "C-1040", "C-1023", "C-1088"]
unique_customers = set(customer_ids)

print("Unique customer count:", len(unique_customers))
print("Customer IDs:", sorted(unique_customers))
```

**Output**

```text
Unique customer count: 3
Customer IDs: ['C-1023', 'C-1040', 'C-1088']
```

The set removes repeated customer IDs. Use the `seen` pattern when first-seen order matters.

## 9. Product category comparison

Compare the categories sold by two branches. Shared categories show common stock. Differences show branch-specific stock.

```python
dhaka_categories = {"rice", "oil", "lentils", "sugar"}
chattogram_categories = {"oil", "sugar", "tea"}

print("Shared:", sorted(dhaka_categories & chattogram_categories))
print("Dhaka only:", sorted(dhaka_categories - chattogram_categories))
print("Chattogram only:", sorted(chattogram_categories - dhaka_categories))
```

**Output**

```text
Shared: ['oil', 'sugar']
Dhaka only: ['lentils', 'rice']
Chattogram only: ['tea']
```

Intersection shows shared categories. Difference shows branch-specific categories.

## 10. An ordered unique report

A set knows uniqueness, not display order. Use a `seen` set and a `unique_in_order` list together.

```python
invoice_rows = ["INV-003", "INV-001", "INV-003", "INV-002", "INV-001"]
seen = set()
unique_in_order = []

for invoice in invoice_rows:
    if invoice not in seen:
        seen.add(invoice)
        unique_in_order.append(invoice)

print("Unique in source order:", unique_in_order)
```

**Output**

```text
Unique in source order: ['INV-003', 'INV-001', 'INV-002']
```

`seen` blocks duplicates. The list preserves the first-seen order.

## 11. A complete business audit

The boss wants row count, unique count, duplicate count, and duplicate references.

```python
invoice_rows = [
    "INV-2024-007",
    "INV-2024-008",
    "INV-2024-007",
    "INV-2024-009",
    "INV-2024-008",
]

seen = set()
duplicates = []

for invoice in invoice_rows:
    if invoice in seen:
        if invoice not in duplicates:
            duplicates.append(invoice)
    else:
        seen.add(invoice)

print("Rows:", len(invoice_rows))
print("Unique:", len(seen))
print("Duplicate references:", duplicates)
print("Duplicate count:", len(duplicates))
```

**Output**

```text
Rows: 5
Unique: 3
Duplicate references: ['INV-2024-007', 'INV-2024-008']
Duplicate count: 2
```

This report separates row-level problems from unique business records.

## 12. Synthesis table

| Tool | Job | When to use it |
|---|---|---|
| `set(items)` | unique values | counts or membership |
| `seen` set | remember earlier items | duplicate scans |
| `duplicates` list | duplicate report order | audit output |
| `a & b` | shared values | branch or category comparison |
| `a - b` | one-sided values | branch-specific categories |
| `sorted(set)` | ordered display | readable summaries |

## 13. Troubleshooting

### Problem 1: The duplicate names are missing
- **Plain meaning:** making a set does not retain repeated-row history.
- **Likely cause:** the original list was not scanned.
- **Step-by-step fix:** keep a `seen` set and append repeated items to a duplicate list.
- **Prevention:** use both a list and a set for duplicate detection.

### Problem 2: The same name appears many times in the duplicate list
- **Plain meaning:** every repeated row was reported.
- **Likely cause:** there was no `invoice not in duplicates` check.
- **Step-by-step fix:** check membership before appending.
- **Prevention:** define the audit rule as one duplicate reference per name.

### Problem 3: The unique report order changes
- **Plain meaning:** sets do not promise order.
- **Likely cause:** the set was displayed directly.
- **Step-by-step fix:** use `sorted()` for stable order, or use `seen` with a list.
- **Prevention:** keep the set for counting and the list for display.

### Problem 4: The category comparison is backwards
- **Plain meaning:** difference depends on the first set.
- **Likely cause:** `chattogram - dhaka` was used for Dhaka-only categories.
- **Step-by-step fix:** use `dhaka - chattogram`.
- **Prevention:** read it as “first branch minus second branch”.

## 14. Common Misconceptions

1. **Wrong:** a set can keep duplicates → **Truth:** each value appears once.
2. **Wrong:** a set tells you the duplicate row → **Truth:** scan the original list for positions.
3. **Wrong:** `len(set(rows))` gives the duplicate count → **Truth:** it gives the unique count.
4. **Wrong:** a set always preserves source order → **Truth:** use a list or `sorted()`.
5. **Wrong:** union is enough for category comparison → **Truth:** use intersection for shared items and difference for branch-specific items.
