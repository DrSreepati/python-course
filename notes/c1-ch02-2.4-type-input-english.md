## 1. What `type()` shows

`type()` is a built-in Python function. It reports a value’s class.

```python
daily_sales = 12000
customer = "Rahim Traders"
paid = True

print(type(daily_sales))
print(type(customer))
print(type(paid))
```

**Output**

```text
<class 'int'>
<class 'str'>
<class 'bool'>
```

`daily_sales` is an integer. `customer` is a string. `paid` is Boolean. `type()` reports the value. It does not change it.

## 2. Inspecting business values

A business record can contain numbers, text, and missing values.

```python
customer = "Karim Store"
balance = None
invoice_count = 12

print(type(customer))
print(type(balance))
print(type(invoice_count))
```

**Output**

```text
<class 'str'>
<class 'NoneType'>
<class 'int'>
```

The name is text. The unknown balance is `NoneType`. The invoice count is an integer. This check can expose bad data.

## 3. What `input()` does

`input()` waits for text from the user in the terminal. The response returns when the user presses Enter.

```python
customer_name = input("Customer name: ")
print("Customer:", customer_name)
```

**Output, with `Rahim Traders` entered**

```text
Customer name: Rahim Traders
Customer: Rahim Traders
```

The prompt tells the user what to enter. The response is stored in `customer_name`. The next line prints it.

## 4. The input prompt

A prompt is a short instruction inside `input()`. A useful prompt names the field and may show a default.

```python
invoice_number = input("Invoice number [INV-2024-007]: ")
if invoice_number == "":
    invoice_number = "INV-2024-007"
print(invoice_number)
```

**Output, when the user presses Enter**

```text
Invoice number [INV-2024-007]:
INV-2024-007
```

Blank input gives an empty string, `""`. The `if` statement detects it and stores the default invoice number.

## 5. Input always returns a string

Even when the user types a number, `input()` first returns a string.

```python
quantity = input("Quantity: ")
print(quantity)
print(type(quantity))
```

**Output, with `6` entered**

```text
Quantity: 6
6
<class 'str'>
```

The screen shows `6`, but `quantity` has type `str`. In subtopic 2.5, type casting will make it a number.

## 6. Blank input and `None`

Blank input is not automatically `None`. `input()` returns `""`. The program may then choose `None`.

```python
note_text = input("Note [optional]: ")
if note_text == "":
    note_text = None
print(note_text)
```

**Output, when the user presses Enter**

```text
Note [optional]:
None
```

The blank response starts as an empty string. The business rule changes it to `None`, meaning a missing note.

## 7. Checking input data

Check whether user data is acceptable for the business field.

```python
customer_code = input("Customer code [C-1023]: ")
if customer_code == "":
    customer_code = None

if customer_code is None:
    print("Customer code is missing")
else:
    print("Customer code:", customer_code)
```

**Output, when the user presses Enter**

```text
Customer code [C-1023]:
Customer code is missing
```

The blank response becomes `None`. The `is None` test detects the missing code, so the incomplete record is not reported as valid.

## 8. Building a business record

Several inputs can build a small sales record. Each input result starts as a string.

```python
customer = input("Customer [Rahim Traders]: ") or "Rahim Traders"
invoice_number = input("Invoice [INV-2024-007]: ") or "INV-2024-007"
print(customer, invoice_number)
```

**Output, when the user presses Enter twice**

```text
Customer [Rahim Traders]: Invoice [INV-2024-007]: Rahim Traders INV-2024-007
```

`or` chooses the default when the response is an empty string. Both fields are text, so strings are suitable.

## 9. Input and arithmetic

Do not add an integer directly to a quantity from `input()`. Inspect the type first.

```python
quantity = input("Quantity [6]: ") or "6"
print(type(quantity))
print("The quantity is text:", quantity)
```

**Output, when the user presses Enter**

```text
Quantity [6]: <class 'str'>
The quantity is text: 6
```

`quantity` is still a string. Arithmetic such as `quantity + 100` will fail. Type casting is the next step.

## 10. Preparing for type casting

Today we inspected the type. The next subtopic uses `int()` to make a text number.

```python
quantity_text = "6"
print(type(quantity_text))

quantity_number = int(quantity_text)
print(type(quantity_number))
```

**Output**

```text
<class 'str'>
<class 'int'>
```

The first value is text. `int()` changes it to an integer. Remember the boundary: `input()` reads, while type casting changes.

## Troubleshooting

### Problem 1: User types `6`, but quantity is not a number

- **What is happening:** `type(quantity)` reports `str`.
- **Most likely cause:** `input()` returns every response as text.
- **Step-by-step fix:** 1. Print `type(quantity)`. 2. Identify the text number. 3. Learn `int()` in the next lesson. 4. Check the type again.
- **How to prevent it:** Write the expected type beside each input field.

### Problem 2: Blank input seems to be `None`

- **What is happening:** Pressing Enter gives `""`, not `None`.
- **Most likely cause:** Empty text and missing data were treated as the same.
- **Step-by-step fix:** 1. Test `value == ""`. 2. Apply the business rule. 3. Store `None` when appropriate. 4. Later test with `value is None`.
- **How to prevent it:** Decide the blank-input policy before writing the program.

### Problem 3: Prompt and response are confused

- **What is happening:** The prompt seems to be stored as the input value.
- **Most likely cause:** The prompt string was confused with the response.
- **Step-by-step fix:** 1. Treat the prompt as an instruction. 2. Store the response in a variable. 3. Print the variable. 4. Inspect its type.
- **How to prevent it:** Make prompts name the field and show a useful default.

### Problem 4: Arithmetic fails after input

- **What is happening:** Adding a number to quantity raises an error.
- **Most likely cause:** A string and an integer were used together.
- **Step-by-step fix:** 1. Inspect `type(quantity)`. 2. Confirm it is text. 3. Learn and use `int()` in the next lesson. 4. Then run the arithmetic.
- **How to prevent it:** Validate and convert input before calculations.

## Common Misconceptions

1. **Wrong claim:** `input()` returns a user’s number as an integer. **Truth:** `input()` always returns a string.
2. **Wrong claim:** Blank input is automatically `None`. **Truth:** Blank input is `""`; code may change it to `None`.
3. **Wrong claim:** `type()` changes a value. **Truth:** `type()` only reports the value’s type.
4. **Wrong claim:** The prompt is the user’s data. **Truth:** The prompt is an instruction. The response is separate.
5. **Wrong claim:** A string number can be added to an integer. **Truth:** Type casting is needed first.
