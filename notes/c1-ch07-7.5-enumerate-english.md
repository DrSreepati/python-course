## 6. A list loop and manual counter

Use an ordinary `for` loop when you need only values.

```python
sales = [12000, 9500, 8800]

for sale in sales:
    print(sale)
```

**Output**

```text
12000
9500
8800
```

- `sale` receives one item at a time.
- A separate counter is needed when position matters.

## 7. A manual counter

The older approach updates the counter yourself.

```python
sales = [12000, 9500, 8800]
day_number = 1

for sale in sales:
    print(f"Day {day_number}: {sale}")
    day_number += 1
```

**Output**

```text
Day 1: 12000
Day 2: 9500
Day 3: 8800
```

- `day_number` is the report label.
- Without `+= 1`, every line repeats the same day.
- The counter and list position are separate state.

## 8. `enumerate`

`enumerate()` supplies a position and value together.

```python
sales = [12000, 9500, 8800]

for index, sale in enumerate(sales):
    print(f"Index {index}: {sale}")
```

**Output**

```text
Index 0: 12000
Index 1: 9500
Index 2: 8800
```

- `index` is zero-based.
- `sale` is the current value.
- No manual counter update is needed.

## 9. `start=1`

Use `start=1` for a customer-facing day report.

```python
sales = [12000, 9500, 8800]

for day_number, sale in enumerate(sales, start=1):
    print(f"Day {day_number}: {sale}")
```

**Output**

```text
Day 1: 12000
Day 2: 9500
Day 3: 8800
```

- The first list item still has index zero.
- Only the displayed counter starts at one.
- This makes reports easier to read.

## 10. Customer and nested row reports

`enumerate()` can number rows in a customer report.

```python
customers = ["Rahim Traders", "Karim Store", "Jahid Enterprise"]
balances = [50000, 32000, 71000]

for customer_number, customer in enumerate(customers, start=1):
    print(f"Customer {customer_number}: {customer}, balance {balances[customer_number - 1]}")
```

**Output**

```text
Customer 1: Rahim Traders, balance 50000
Customer 2: Karim Store, balance 32000
Customer 3: Jahid Enterprise, balance 71000
```

- The display number is one-based.
- The balance index is `customer_number - 1`.
- The parallel lists remain aligned.

## 11. An audit report

An audit message is clear when it includes both position and value.

```python
references = ["INV-2024-007", "INV-2024-008", "INV-2024-009"]

for reference_number, reference in enumerate(references, start=1):
    print(f"Review {reference_number}: {reference}")
```

**Output**

```text
Review 1: INV-2024-007
Review 2: INV-2024-008
Review 3: INV-2024-009
```

- `reference_number` is the report sequence.
- `reference` is the invoice code.
- The code itself is unchanged.

## 12. Troubleshooting

### Problem 1
- What happens: the report starts at day zero.
- Likely cause: `enumerate(sales)` defaults to zero.
- Fix: use `enumerate(sales, start=1)`.
- Prevention: separate technical indexes from business labels.

### Problem 2
- What happens: the same day repeats.
- Likely cause: the manual counter was not updated.
- Fix: add `counter += 1` at the loop’s end.
- Prevention: use `enumerate()` when a position is needed.

### Problem 3
- What happens: customers and balances do not match.
- Likely cause: a one-based display number was used as a list index.
- Fix: subtract one, or use the zero-based enumerate index.
- Prevention: check parallel-list positions carefully.

### Problem 4
- What happens: `ValueError: too many values to unpack` appears.
- Likely cause: an enumerate pair was assigned to one variable.
- Fix: write `for index, value in enumerate(items)`.
- Prevention: remember that enumerate returns two values.

## 13. Common Misconceptions

1. **Wrong:** `enumerate()` changes values → **Truth:** it supplies position and value.
2. **Wrong:** `start=1` changes list indexes → **Truth:** it changes only the returned counter.
3. **Wrong:** manual counters are always simpler → **Truth:** forgotten updates create bugs.
4. **Wrong:** enumerate returns only an index → **Truth:** it returns an index and item.
5. **Wrong:** a display number is a list index → **Truth:** one-based labels need one subtracted.

## 15. Quiz

1. What does `enumerate()` provide?  
   a) position and value  b) only total  c) only the final item  
   **Answer: a**, because it returns a pair.
2. What is the default enumeration start?  
   a) 1  b) 0  c) -1  
   **Answer: b**, because Python is zero-based.
3. How do you start a business day label at one?  
   a) `start=1`  b) `reverse=True`  c) `len=1`  
   **Answer: a**, because the counter starts at one.
4. What is `i` in `for i, value in enumerate(values)`?  
   a) index  b) value  c) total  
   **Answer: a**, because it is the first returned item.
5. What is the main manual-counter risk?  
   a) forgetting the update  b) creating a list  c) calculating a sum  
   **Answer: a**, because state must be updated manually.
6. How do you get a list index from a one-based customer number?  
   a) number - 1  b) number + 1  c) number * 2  
   **Answer: a**, because indexes start at zero.
7. Does `enumerate()` change the original list?  
   a) no  b) always yes  c) it deletes the list  
   **Answer: a**, because it only supplies iteration pairs.

## 16. Key Idea

`enumerate()` gives a list loop both position and value. The technical index stays zero-based. `start=1` makes business labels clear.
