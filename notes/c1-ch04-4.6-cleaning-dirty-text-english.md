## 1. What dirty text is

Dirty text contains extra spaces, inconsistent capital letters or incorrect separators. It may not look broken, but it can cause problems in comparisons, reports and lookups.

```python
raw_customer = "  rahim TRADERS  "
raw_invoice = " inv/2024/007 "

print(raw_customer)
print(raw_invoice)
```

**Output**

```text
  rahim TRADERS  
 inv/2024/007 
```

The customer name has outer spaces and mixed case. The invoice has outer spaces and uses slashes as separators.

Important lines:

- `raw_customer` keeps the original form.
- `raw_invoice` keeps the user-entered invoice reference.
- `print()` helps us see the raw data problem.

## 2. Recognising extra spaces

Outer spaces may not be visible in a report, but they can break a comparison. Use `strip()` to clean both edges.

```python
raw_name = "  Rahim Traders  "
clean_name = raw_name.strip()

print(raw_name == "Rahim Traders")
print(clean_name == "Rahim Traders")
```

**Output**

```text
False
True
```

The first comparison is `False` because the raw value has extra spaces. After `strip()`, the cleaned value matches the expected name.

`strip()` does not remove the space between `Rahim` and `Traders`. That internal separator is useful here.

## 3. Standardising mixed case

One customer may appear as `Rahim Traders`, `RAHIM TRADERS` or `rahim traders`. A standard case helps us compare them.

```python
name_a = "Rahim Traders"
name_b = "RAHIM TRADERS"

key_a = name_a.lower()
key_b = name_b.lower()

print(key_a)
print(key_b)
print(key_a == key_b)
```

**Output**

```text
rahim traders
rahim traders
True
```

The display forms differ, but the lowercase comparison keys match. A comparison key is a new form for matching. It is not necessarily the display form.

## 4. Understanding stray symbols

A stray symbol is a character that does not belong in the required input format, or should be a different symbol. For example, an invoice may use slashes when the standard uses hyphens.

```python
raw_invoice = "INV/2024/007"
clean_invoice = raw_invoice.replace("/", "-")

print(raw_invoice)
print(clean_invoice)
```

**Output**

```text
INV/2024/007
INV-2024-007
```

The slashes become hyphens. The original invoice remains available. Replacing a known wrong symbol is safer than deleting every symbol.

## 5. Cleaning customer names

Customer-name cleaning often removes outer spaces and creates a lowercase comparison key. Keep a readable display name separately.

```python
raw_customer = "  RAHIM traders  "

display_name = raw_customer.strip()
customer_key = display_name.lower()

print(display_name)
print(customer_key)
```

**Output**

```text
RAHIM traders
rahim traders
```

`display_name` keeps the original case after removing outer spaces. `customer_key` is lowercase for matching. One input can have separate display and comparison forms.

If a report needs title case, `title()` can be considered later. Today's workflow uses the methods already taught.

## 6. Cleaning invoice codes

Invoice cleaning can fix outer spaces, mixed case and a known separator together.

```python
raw_invoice = " inv/2024/007 "

clean_invoice = raw_invoice.strip().upper().replace("/", "-")

print(clean_invoice)
print(clean_invoice.startswith("INV-"))
print(clean_invoice.endswith("007"))
```

**Output**

```text
INV-2024-007
True
True
```

Cleaning order:

- `strip()` removes outer spaces.
- `upper()` standardises letters.
- `replace("/", "-")` standardises the separator.
- `startswith()` and `endswith()` check the final result.

## 7. Cleaning order

The order of methods can affect the result. It is usually simple to remove outer whitespace, standardise case and then replace known symbols.

```python
raw_code = "  inv/2024/007  "

step_1 = raw_code.strip()
step_2 = step_1.upper()
step_3 = step_2.replace("/", "-")

print(step_1)
print(step_2)
print(step_3)
```

**Output**

```text
inv/2024/007
INV/2024/007
INV-2024-007
```

Each step has its own variable. This makes debugging easier and shows exactly what each method changed.

The same workflow can be written on one line:

```python
clean_code = raw_code.strip().upper().replace("/", "-")
print(clean_code)
```

**Output**

```text
INV-2024-007
```

## 8. Keeping raw and cleaned values

Do not throw away raw business data during cleaning. The original may be needed for an audit or for finding the source of an error.

```python
raw_name = "  Karim STORE  "
clean_name = raw_name.strip().lower()

print(f"Raw: {raw_name}")
print(f"Clean key: {clean_name}")
```

**Output**

```text
Raw:   Karim STORE  
Clean key: karim store
```

`raw_name` is the user input. `clean_name` is the matching key. Separate variables make the two purposes clear.

## 9. Checking a cleaning result

Do not assume cleaning is complete. Check the result with an expected prefix, suffix or separator count.

```python
raw_invoice = " inv/2024/007 "
clean_invoice = raw_invoice.strip().upper().replace("/", "-")

print(clean_invoice.count("/"))
print(clean_invoice.count("-"))
print(clean_invoice.startswith("INV-"))
```

**Output**

```text
0
2
True
```

The cleaned invoice has no slash, two hyphens and the expected prefix. These checks provide simple evidence for business rules.

`True` means these checks pass. It does not prove that every possible data problem is gone.

## 10. A safe business cleaning workflow

Customer and invoice fields can need different rules. Keep a customer's internal space. Replace a known invoice slash with a hyphen.

```python
raw_customer = "  rahim TRADERS  "
raw_invoice = " inv/2024/007 "

customer_key = raw_customer.strip().lower()
clean_invoice = raw_invoice.strip().upper().replace("/", "-")

print(f"Customer key: {customer_key}")
print(f"Invoice: {clean_invoice}")
print(clean_invoice.startswith("INV-"))
print(clean_invoice.endswith("007"))
```

**Output**

```text
Customer key: rahim traders
Invoice: INV-2024-007
True
True
```

The internal customer space remains. The invoice slash becomes a hyphen. We choose rules according to each field's business meaning instead of applying one blind rule everywhere.

## Synthesis table

| Dirty problem | Safe method | Example | Result |
|---|---|---|---|
| Outer spaces | `strip()` | `"  C-1023  ".strip()` | `C-1023` |
| Mixed case | `lower()` | `"RAHIM".lower()` | `rahim` |
| Report display case | `upper()` | `"inv".upper()` | `INV` |
| Known wrong symbol | `replace()` | `"INV/1".replace("/", "-")` | `INV-1` |
| Prefix check | `startswith()` | `"INV-1".startswith("INV-")` | `True` |
| Suffix check | `endswith()` | `"INV-007".endswith("007")` | `True` |
| Separator check | `count()` | `"INV-1".count("-")` | `1` |
| Audit trail | keep two variables | `raw`, `clean` | Both values |

## Troubleshooting

### Problem 1: The name still does not match

- What is happening: the same customer appears to produce `False`.
- Most likely cause: outer spaces or mixed case remain.
- Step-by-step fix: apply `strip().lower()` to both inputs, then compare the keys.
- Prevention: keep a standard display value and comparison key.

### Problem 2: A useful invoice separator disappeared

- What is happening: the cleaned code is no longer readable or valid.
- Most likely cause: every symbol or every space was removed blindly.
- Step-by-step fix: inspect the raw format, replace only the known wrong symbol, then check the prefix and suffix.
- Prevention: understand each symbol's business meaning.

### Problem 3: The cleaning order gives a wrong result

- What is happening: the expected standard form does not appear.
- Most likely cause: whitespace, case and separator rules were applied in an unclear order.
- Step-by-step fix: print `strip()`, case conversion and replacement as separate steps.
- Prevention: use named intermediate variables.

### Problem 4: The raw data is gone

- What is happening: nobody can see what the user originally entered.
- Most likely cause: the cleaned result overwrote the raw variable.
- Step-by-step fix: keep the raw value in one variable and create the cleaned value in another.
- Prevention: never overwrite raw input when an audit may be needed.

## Common Misconceptions

1. **Wrong:** every dirty text field needs every space removed -> **Truth:** internal spaces may have business meaning.
2. **Wrong:** uppercase alone cleans customer data -> **Truth:** whitespace and stray symbols need separate handling.
3. **Wrong:** `replace("/", "")` is safe for every invoice -> **Truth:** removing separators can destroy code structure.
4. **Wrong:** a passing cleaned result means the raw value is useless -> **Truth:** raw data helps audits and debugging.
5. **Wrong:** one cleaning rule fits every field -> **Truth:** customer names and invoice codes may need different rules.

## Key Idea

Dirty-text cleaning means understanding raw input and creating a standard form step by step. `strip()` handles outer spaces, `lower()` or `upper()` handles case, and `replace()` handles known stray symbols. Keeping raw and cleaned values separately supports safe business audits.

**Rhyme 1:** Remove spaces, set the case, give symbols their plan,  
**Rhyme 2:** Keep raw and clean together, audits understand.
