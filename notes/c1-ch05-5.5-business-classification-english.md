## 6. Discount eligibility

An order needs both a large value and a safe balance.

```python
order_amount = 12000
customer_balance = 32000

if order_amount >= 10000 and customer_balance >= 30000:
    discount_status = "Eligible"
else:
    discount_status = "Not eligible"

print(discount_status)
```

**Output**

```text
Eligible
```

`>=` accepts the exact threshold. `and` checks both business gates.

## 7. Overdue status

An account is overdue when money is due, days have passed, and payment is missing.

```python
outstanding = 50000
days_overdue = 12
payment_received = False

if outstanding > 0 and days_overdue > 0 and not payment_received:
    status = "Overdue"
elif outstanding == 0 or payment_received:
    status = "Clear"
else:
    status = "Review"

print(status)
```

**Output**

```text
Overdue
```

All three overdue tests are true.

## 8. Budget variance

Actual cost above budget is over budget. Below is under budget. Equal is on budget.

```python
budget = 40000
actual_cost = 42500

if actual_cost > budget:
    variance_status = "Over budget"
elif actual_cost < budget:
    variance_status = "Under budget"
else:
    variance_status = "On budget"

print(variance_status)
```

**Output**

```text
Over budget
```

The greater than and less than branches cover both directions. Equality is the remaining case.

## 9. Profit, loss, and break-even

Positive profit means profit. Negative profit means loss. Zero means break-even.

```python
profit = 0

if profit > 0:
    result = "Profit"
elif profit < 0:
    result = "Loss"
else:
    result = "Break-even"

print(result)
```

**Output**

```text
Break-even
```

Zero has its own business meaning. It is not a loss.

## 10. Payment status

Compare the paid amount with the invoice amount.

```python
invoice_amount = 20000
paid_amount = 12000

if paid_amount == 0:
    payment_status = "Unpaid"
elif paid_amount < invoice_amount:
    payment_status = "Partly paid"
elif paid_amount == invoice_amount:
    payment_status = "Paid"
else:
    payment_status = "Overpaid"

print(payment_status)
```

**Output**

```text
Partly paid
```

Zero comes first. Then partial, exact, and extra payment categories follow.

## 11. One small report

Named status variables make the boss’s report readable.

```python
customer_name = "Jahid Enterprise"
order_amount = 13200
balance = 71000
budget = 40000
actual_cost = 38000
profit = 2500
paid_amount = 20000
invoice_amount = 20000

if order_amount >= 10000 and balance >= 30000:
    discount_status = "Eligible"
else:
    discount_status = "Not eligible"

if actual_cost > budget:
    budget_status = "Over budget"
elif actual_cost < budget:
    budget_status = "Under budget"
else:
    budget_status = "On budget"

if profit > 0:
    profit_status = "Profit"
elif profit < 0:
    profit_status = "Loss"
else:
    profit_status = "Break-even"

if paid_amount == invoice_amount:
    payment_status = "Paid"
else:
    payment_status = "Review payment"

print(customer_name)
print(discount_status)
print(budget_status)
print(profit_status)
print(payment_status)
```

**Output**

```text
Jahid Enterprise
Eligible
Under budget
Profit
Paid
```

Each rule creates one named status. The report prints the statuses in order.

## 13. Troubleshooting

### Problem 1
- What happens: an order of 10000 is rejected.
- Likely cause: `>` was used.
- Fix: use `>=` for an inclusive policy.
- Prevention: test the exact threshold.

### Problem 2
- What happens: zero profit is called a loss.
- Likely cause: `else` was used for loss.
- Fix: add a separate `profit < 0` branch.
- Prevention: write positive, negative, and zero cases.

### Problem 3
- What happens: a partly paid invoice is called paid.
- Likely cause: only `paid_amount > 0` was checked.
- Fix: compare paid amount with invoice amount.
- Prevention: test zero, partial, exact, and extra payment.

### Problem 4
- What happens: under budget is labelled over budget.
- Likely cause: comparison direction is reversed.
- Fix: say actual and budget aloud before choosing the operator.
- Prevention: test 38000 and 42500.

## 14. Common Misconceptions

1. **Wrong:** thresholds exclude equality → **Truth:** `>=` includes equality.
2. **Wrong:** zero profit is loss → **Truth:** zero is break-even.
3. **Wrong:** any positive payment means paid → **Truth:** compare it with the invoice.
4. **Wrong:** one condition creates every status → **Truth:** each report question needs its rule.
5. **Wrong:** branch order does not matter → **Truth:** the first matching branch runs.

## 16. Quiz

1. Which operator joins two required discount gates?  
   a) `and`  b) `or`  c) `not`  
   **Answer: a**, because both conditions must be true.
2. What is actual cost below budget?  
   a) Over budget  b) Under budget  c) Paid  
   **Answer: b**, because actual cost is smaller.
3. What is zero profit?  
   a) Loss  b) Profit  c) Break-even  
   **Answer: c**, because it is neither gain nor loss.
4. What is paid amount below the invoice?  
   a) Partly paid  b) Overpaid  c) Unpaid  
   **Answer: a**, because some payment has arrived.
5. What does `>=` do?  
   a) excludes equality  b) includes equality  c) makes a string  
   **Answer: b**, because it includes the boundary.
6. How does an overdue rule show missing payment?  
   a) `not payment_received`  b) `payment_received`  c) exact equality  
   **Answer: a**, because payment has not arrived.
7. Which branch runs in an if-elif-else chain?  
   a) every matching branch  b) the first matching branch  c) no branch  
   **Answer: b**, because the chain stops at the first true test.
