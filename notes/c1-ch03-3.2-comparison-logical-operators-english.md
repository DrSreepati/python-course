## 1. What comparison means

A comparison operator tests a relationship between values. Its result is `True` or `False`.

```python
sales = 12000
target = 10000

print(sales > target)
```

**Output**

```text
True
```

Sales are greater than the target. Therefore, the result is `True`.

## 2. Equality and inequality

`==` asks whether two values are equal. `!=` asks whether they are different. `=` assigns a value. It does not compare values.

```python
customer_code = "C-1023"
expected_code = "C-1023"

print(customer_code == expected_code)
print(customer_code != "C-9999")
```

**Output**

```text
True
True
```

The two codes match. The two different codes are not equal.

## 3. Greater and smaller values

`>` means greater than. `<` means less than. These operators help with profit and stock rules.

```python
profit = 3500
reorder_level = 20
stock = 15

print(profit > 0)
print(stock < reorder_level)
```

**Output**

```text
True
True
```

Profit is above zero. Stock is below the reorder level.

## 4. Boundary comparisons

`>=` means greater than or equal to. `<=` means less than or equal to. A customer may qualify when the order exactly meets the minimum.

```python
order_amount = 50000
discount_limit = 50000

print(order_amount >= discount_limit)
print(order_amount <= discount_limit)
```

**Output**

```text
True
True
```

The values are equal. Both boundary comparisons are true.

## 5. Boolean results

A comparison returns a Boolean value. Store it in a variable for a report or later rule.

```python
amount = 32000
minimum_order = 10000
large_order = amount >= minimum_order

print(large_order)
print(type(large_order))
```

**Output**

```text
True
<class 'bool'>
```

`large_order` stores the comparison result. Its type is `bool`.

## 6. `and`

With `and`, both conditions must be true. An order may need a minimum amount and a completed payment.

```python
order_amount = 32000
minimum_order = 10000
paid = True

eligible = order_amount >= minimum_order and paid == True
print(eligible)
```

**Output**

```text
True
```

Both conditions are true. Therefore, the `and` result is true.

## 7. `or`

With `or`, at least one condition must be true. Payment may arrive by cash or bank transfer.

```python
cash_received = False
bank_received = True

payment_received = cash_received or bank_received
print(payment_received)
```

**Output**

```text
True
```

Cash was not received. Bank payment was received. Therefore, the `or` result is `True`.

## 8. `not`

`not` reverses a Boolean result. It changes `True` to `False`, and `False` to `True`.

```python
stock_available = False
stock_missing = not stock_available

print(stock_missing)
```

**Output**

```text
True
```

Stock is not available. Therefore, stock is missing.

## 9. A discount rule

Real rules combine comparison and logic. Here, the order must meet the minimum and be paid.

```python
order_amount = 71000
minimum_order = 50000
paid = True

discount_eligible = order_amount >= minimum_order and paid
print(discount_eligible)
```

**Output**

```text
True
```

The order meets the minimum. Payment is also true. The customer is eligible.

## 10. Checking conditions

Boundary testing matters. Test just below, exactly at, and just above a minimum.

```python
minimum_order = 50000

below = 49999 >= minimum_order
equal = 50000 >= minimum_order
above = 50001 >= minimum_order

print(below)
print(equal)
print(above)
```

**Output**

```text
False
True
True
```

49999 is not eligible. 50000 and 50001 are eligible. These cases test the boundary.

## Troubleshooting

### Problem 1: A comparison changes a value

- What is happening: a variable receives a new value instead of being compared.
- Most likely cause: `=` was written instead of `==`.
- Fix: use `=` for assignment and `==` for equality checks.
- Prevention: read the condition aloud as “is equal to?”

### Problem 2: The minimum order is rejected

- What is happening: an order exactly at the limit is rejected.
- Most likely cause: `>` was used although equality is allowed.
- Fix: use `>=`, then test below, equal and above.
- Prevention: state the boundary rule clearly.

### Problem 3: An `and` condition is false

- What is happening: one true condition does not make the full result true.
- Most likely cause: `and` requires every condition to be true.
- Fix: print each condition separately.
- Prevention: break a complex rule into small checks.

### Problem 4: `or` accepts an incomplete payment

- What is happening: one payment condition accepts the whole payment.
- Most likely cause: `or` means at least one true condition.
- Fix: decide whether the policy needs `and` or `or`.
- Prevention: write the payment policy in words first.

## Common Misconceptions

1. **Wrong:** `=` and `==` are the same → **Truth:** `=` assigns, while `==` compares.
2. **Wrong:** `and` needs one true condition → **Truth:** `and` needs all conditions true.
3. **Wrong:** `or` needs every condition true → **Truth:** one true condition is enough.
4. **Wrong:** `not` deletes a value → **Truth:** `not` reverses a Boolean result.
5. **Wrong:** `>` and `>=` are the same → **Truth:** `>=` also accepts equality.

## Quiz

### 1. What does `==` test?

a. Whether two values are equal  
b. Whether a value is deleted  
c. Whether a value is multiplied  

**Answer: a.** Equality checks whether values match.

### 2. What is the result of `8 > 5`?

a. `8`  
b. `True`  
c. `False`  

**Answer: b.** Eight is greater than five.

### 3. What is `23 >= 23`?

a. `False`  
b. `23`  
c. `True`  

**Answer: c.** `>=` accepts equality.

### 4. When is `and` true?

a. When one condition is true  
b. When every condition is true  
c. When there is no condition  

**Answer: b.** Every part must be true.

### 5. What is `False or True`?

a. `True`  
b. `False`  
c. `None`  

**Answer: a.** One true condition is enough for `or`.

### 6. What is `not True`?

a. `True`  
b. `1`  
c. `False`  

**Answer: c.** `not` reverses the Boolean value.

### 7. Which operator includes equality at a minimum?

a. `>=`  
b. `>`  
c. `!=`  

**Answer: a.** Greater than or equal includes the limit.

## Key Idea

Comparison operators test business relationships and return Boolean values. Use `and`, `or` and `not` to combine rules.

**Rhyme 1:** Equal takes two marks, greater takes one, choose the rule with care.  
**Rhyme 2:** `and` needs all, `or` needs one, `not` turns truth elsewhere.
