## 1. What `split()` does

`split()` breaks a string at a chosen separator and creates a list. A list is an ordered collection of values. This helps us separate an invoice code.

```python
invoice_no = "INV-2024-007"
parts = invoice_no.split("-")

print(parts)
print(type(parts))
```

**Output**

```text
['INV', '2024', '007']
<class 'list'>
```

The string breaks at each hyphen. The result is a list with the prefix, year and serial.

Important lines:

- `invoice_no` stores the original reference.
- `split("-")` breaks the text at every hyphen.
- `parts` stores the list result.

## 2. Splitting an invoice with a separator

The argument in `split(separator)` tells Python where to divide the text. A slash-based invoice can be split in the same way.

```python
raw_invoice = "INV/2024/007"
parts = raw_invoice.split("/")

print(parts[0])
print(parts[1])
print(parts[2])
```

**Output**

```text
INV
2024
007
```

The separator is a slash. `parts[0]` is the prefix, `parts[1]` is the year and `parts[2]` is the serial.

If the separator does not occur, `split()` keeps the whole string as one item. Therefore, understand the input format first.

## 3. The result of `split()`

Because `split()` returns a list, we can read each item by index. Empty items can also appear when separators are next to each other.

```python
customer_code = "C-1023"
parts = customer_code.split("-")

print(parts)
print(parts[0])
print(parts[1])
```

**Output**

```text
['C', '1023']
C
1023
```

The customer code becomes two parts. The prefix and numeric ID are separate list items.

One warning:

```python
text = "INV--007"
print(text.split("-"))
```

**Output**

```text
['INV', '', '007']
```

Two adjacent hyphens create an empty string in the middle. This is not an error, but it signals a possible data problem.

## 4. What `join()` does

`join()` joins text items with a separator. Its syntax is `separator.join(items)`. The separator comes before the method.

```python
parts = ["INV", "2024", "007"]
invoice_no = "-".join(parts)

print(invoice_no)
```

**Output**

```text
INV-2024-007
```

The hyphen goes between the list items. `join()` creates a new string.

Important rules:

- `"-".join(parts)` means join with hyphens.
- `"".join(parts)` means join without a separator.
- `parts.join("-")` is wrong because the separator owns the `join()` method.

## 5. Joining parts with a separator

Business reports may join values with commas, slashes or new lines.

```python
customers = ["Rahim Traders", "Karim Store", "Jahid Enterprise"]

comma_report = ", ".join(customers)
line_report = "\n".join(customers)

print(comma_report)
print(line_report)
```

**Output**

```text
Rahim Traders, Karim Store, Jahid Enterprise
Rahim Traders
Karim Store
Jahid Enterprise
```

`", ".join(customers)` creates one report line. `"\n".join(customers)` places each customer on a new line.

It is safest when every item passed to `join()` is a string. Numbers will need conversion before joining.

## 6. Finding a position with `find()`

`find(part)` returns the first index where a part begins. It searches from the left.

```python
invoice_no = "INV-2024-007"

print(invoice_no.find("INV"))
print(invoice_no.find("2024"))
print(invoice_no.find("-"))
```

**Output**

```text
0
4
3
```

`INV` begins at index 0. `2024` begins at index 4. The first hyphen is at index 3.

`find()` can search for one character or several characters. It returns the first matching position.

## 7. When `find()` finds nothing

If the search text is absent, `find()` returns `-1`. We can use this result to check whether text exists.

```python
invoice_no = "INV-2024-007"

position = invoice_no.find("2025")
print(position)
print(position == -1)
```

**Output**

```text
-1
True
```

`2025` is not in the invoice. `-1` is not a real valid index. It signals that the text was not found.

Checking a found separator:

```python
code = "C-1023"

if code.find("-") != -1:
    print("Separator found")
```

**Output**

```text
Separator found
```

This condition only demonstrates the `find()` result. Full conditional logic comes in Chapter 5.

## 8. Checking a beginning with `startswith()`

`startswith(prefix)` returns `True` when a string begins with that prefix. Otherwise, it returns `False`.

```python
invoice_no = "INV-2024-007"

print(invoice_no.startswith("INV"))
print(invoice_no.startswith("C-"))
```

**Output**

```text
True
False
```

The invoice begins with `INV`. It does not begin with `C-`. This method is readable for prefix validation.

Remember that it is case-sensitive:

```python
code = "inv-2024-007"
print(code.startswith("INV"))
print(code.upper().startswith("INV"))
```

**Output**

```text
False
True
```

The first comparison has different case. Uppercasing creates a standard form, so the second comparison matches.

## 9. Checking an ending with `endswith()`

`endswith(suffix)` returns `True` when a string ends with that suffix. It helps with file extensions, serial patterns and report labels.

```python
invoice_no = "INV-2024-007"

print(invoice_no.endswith("007"))
print(invoice_no.endswith("2024"))
```

**Output**

```text
True
False
```

The invoice ends with `007`, so the first result is `True`. It does not end with `2024`.

You can check several possible endings with a tuple:

```python
file_name = "sales_report.csv"
print(file_name.endswith((".csv", ".xlsx")))
```

**Output**

```text
True
```

This checks whether the filename ends with `.csv` or `.xlsx`. The tuple is shown only as method input here.

## 10. A business parsing workflow

We can split an invoice reference, check its parts and join it into a standard format.

```python
raw_invoice = " inv/2024/007 "

clean_invoice = raw_invoice.strip().upper()
parts = clean_invoice.split("/")
standard_invoice = "-".join(parts)

print(parts)
print(standard_invoice)
print(standard_invoice.startswith("INV"))
print(standard_invoice.endswith("007"))
```

**Output**

```text
['INV', '2024', '007']
INV-2024-007
True
True
```

Workflow:

- `strip()` removes outer spaces.
- `upper()` standardises case.
- `split("/")` separates invoice parts.
- `join()` creates a standard code with hyphens.
- `startswith()` and `endswith()` check the final format.

## Synthesis table

|---|---|---|---|

| Find a position | `text.find(part)` | `"INV".find("V")` | `2` |
| Check beginning | `text.startswith(prefix)` | `"INV-1".startswith("INV")` | `True` |

| Not-found signal | `find()` result `-1` | `"C".find("X")` | `-1` |

## Troubleshooting

### Problem 1: `split()` returns one whole item

- What is happening: the learner expects three parts, but the list has one item.
- Most likely cause: the input separator and the `split()` separator are different.
- Step-by-step fix: inspect the raw text, then pass the same character to `split()`.
- Prevention: identify the delimiter before writing the method call.

### Problem 2: `join()` gives a syntax error

- What is happening: the text parts do not join.
- Most likely cause: `join()` was written on the list instead of the separator.
- Step-by-step fix: use the pattern `"-".join(parts)`.
- Prevention: remember that the text placed between items owns the `join()` method.

### Problem 3: `find()` returns `-1`

- What is happening: the learner cannot find the expected position.
- Most likely cause: the search text is absent or its case differs.
- Step-by-step fix: check the exact spelling. Use `lower()` or `upper()` when needed.
- Prevention: treat `-1` as a not-found signal, not as a valid index.

### Problem 4: `startswith()` or `endswith()` returns `False`

- What is happening: the text looks similar, but the result is `False`.
- Most likely cause: extra spaces, wrong case or the wrong suffix.
- Step-by-step fix: strip spaces, standardise case and use the exact prefix or suffix.
- Prevention: clean input before validation.

## Common Misconceptions

1. **Wrong:** `split()` returns a new string -> **Truth:** it usually returns a list of string items.
2. **Wrong:** `join()` is a list method -> **Truth:** write `join()` on the separator string.
3. **Wrong:** `find()` returns `None` when text is absent -> **Truth:** it returns `-1`.
4. **Wrong:** `startswith()` ignores case -> **Truth:** it is case-sensitive.
5. **Wrong:** `endswith()` is only for file extensions -> **Truth:** it checks any suffix.

## Key Idea

`split()` breaks text into a list. `join()` joins text items. `find()` locates text. `startswith()` and `endswith()` check boundaries. Business parsing depends on the correct separator, case and whitespace.

**Rhyme 1:** Split makes parts, join makes one,  
**Rhyme 2:** Find checks position, start-end checks the run.
