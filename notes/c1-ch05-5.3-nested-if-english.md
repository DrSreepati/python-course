## 5. What is nested if?

An `if` inside an `if` block is a nested if. In the Dhaka wholesale shop, first check order size. Then check the customer balance.

```python
order_amount = 12000
customer_balance = 32000

if order_amount >= 10000:
    if customer_balance >= 30000:
        print("Discount review approved")
    else:
        print("Hold for balance review")
else:
    print("Order too small")
```

**Output**

```text
Discount review approved
```

The first `if` checks the order gate. The second runs only for a large order. Both comparisons are true.

## 6. Outer and inner conditions

The outer condition checks broad eligibility. The inner condition checks a detail.

```python
customer_name = "Rahim Traders"
order_amount = 9500
customer_balance = 50000

if order_amount >= 10000:
    if customer_balance >= 30000:
        decision = "Review approved"
    else:
        decision = "Review held"
else:
    decision = "Not eligible"

print(f"{customer_name}: {decision}")
```

**Output**

```text
Rahim Traders: Not eligible
```

The data is stored in three variables. The outer test is false. Therefore, the inner test is skipped.

## 7. Nested if-else with three outcomes

The shop can check order size, then payment status.

```python
order_amount = 15000
outstanding = 0

if order_amount >= 10000:
    if outstanding == 0:
        label = "Large order, paid"
    else:
        label = "Large order, payment pending"
else:
    label = "Small order"

print(label)
```

**Output**

```text
Large order, paid
```

The first comparison confirms a large order. The second gives zero outstanding its business meaning.

## 8. Three levels of decision

Several checks can be made in sequence. Keep each indentation level clear.

```python
customer_balance = 71000
order_amount = 13200
profit = 2500

if customer_balance >= 30000:
    if order_amount >= 10000:
        if profit > 0:
            print("Approve profitable credit order")
        else:
            print("Review profit before approval")
    else:
        print("Review order size")
else:
    print("Hold customer account")
```

**Output**

```text
Approve profitable credit order
```

The programme checks account eligibility, order size, and profit in that order. Each inner block belongs to the previous true branch.

## 9. Branch audit and boundaries

Boundary values need special tests. With `>= 10000`, 10000 qualifies, but 9999 does not.

```python
order_amount = 10000
customer_balance = 29999

if order_amount >= 10000:
    if customer_balance >= 30000:
        print("Approve")
    else:
        print("Hold: balance below threshold")
else:
    print("Reject: order below threshold")
```

**Output**

```text
Hold: balance below threshold
```

The order passes its boundary. The balance does not. So the outer true and inner false branches run.

## 10. Reducing needless nesting

Sometimes `and` states the same rule more briefly. Learn the nested form first, then compare it with this form.

```python
order_amount = 12000
customer_balance = 32000

if order_amount >= 10000 and customer_balance >= 30000:
    print("Approve")
else:
    print("Hold")
```

**Output**

```text
Approve
```

`and` requires both conditions to be true. Nested if is clearer when each failure needs a different message.

## 11. Synthesis table

| Job | Suitable tool |
|---|---|
| Test one condition | `if` |
| Choose two paths | `if-else` |
| Choose categories | `if-elif-else` |
| Check eligibility, then detail | nested `if` |
| Require two true conditions | `and` |

## 12. Troubleshooting

### Problem 1
- What happens: the inner message never appears.
- Likely cause: the outer condition is false.
- Fix: print the outer value and test 9999 and 10000.
- Prevention: write the outer false case in a decision table.

### Problem 2
- What happens: the inner `else` gives the wrong message.
- Likely cause: incorrect indentation.
- Fix: align the inner `else` with its inner `if`.
- Prevention: use four spaces for each block.

### Problem 3
- What happens: an order of 10000 is rejected.
- Likely cause: `>` was used.
- Fix: use `>=` for an inclusive threshold.
- Prevention: always test the exact boundary.

### Problem 4
- What happens: approval gives no balance reason.
- Likely cause: all failures share one generic `else`.
- Fix: give outer and inner failures separate messages.
- Prevention: define an output for each business rule.

## 13. Common Misconceptions

1. **Wrong:** the inner `if` always runs → **Truth:** the outer condition must be true.
2. **Wrong:** nesting means a loop → **Truth:** it means one block inside another.
3. **Wrong:** `>=` and `>` are the same → **Truth:** `>=` includes equality.
4. **Wrong:** all nested code should be one line → **Truth:** readable indentation helps audits.
5. **Wrong:** nested if allows only one outcome → **Truth:** each branch may have its own outcome.

## 15. Quiz

1. What is nested if?  
   a) a loop  b) a list  c) an `if` inside another block  
   **Answer: c**, because the inner condition is inside the outer block.
2. When is the inner condition tested?  
   a) when the outer condition is true  b) always  c) at the end  
   **Answer: a**, because execution must enter the outer block.
3. Which includes 10000?  
   a) `>`  b) `>=`  c) `<`  
   **Answer: b**, because equality is accepted.
4. What does `and` require?  
   a) at least one true  b) both true  c) all false  
   **Answer: b**, because both operands must be true.
5. Where does a nested `else` align?  
   a) with the inner `if`  b) with `print`  c) with the file  
   **Answer: a**, because it is that condition’s fallback.
6. Is `9500 >= 10000` true?  
   a) True  b) None  c) False  
   **Answer: c**, because 9500 is smaller.
7. What is best when failure reasons differ?  
   a) always one line  b) clear branches  c) delete variables  
   **Answer: b**, because branches can show the reason.

## 16. Key Idea

Nested if means checking a second door after the first. The outer rule checks eligibility. The inner rule checks detail. Use `and` for a short shared rule, and nesting for separate reasons.
