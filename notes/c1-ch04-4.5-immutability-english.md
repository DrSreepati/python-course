## 1. What immutability means

Immutability means that the inside of a value cannot be changed directly after creation. Python strings are immutable. We cannot update a string character through its index.

```python
customer_code = "C-1023"

print(customer_code)
print(customer_code[0])
```

**Output**

```text
C-1023
C
```

An index can read a character. It cannot assign a new character to the original string.

Important difference:

- A string is immutable, so its characters cannot be updated directly.
- A variable can still be assigned a new string.

## 2. Direct character assignment

A list item can be updated by index. A string character cannot. Therefore, the following code raises an error.

```python
invoice_no = "INV-2024-007"
invoice_no[0] = "X"
```

**Output**

```text
TypeError: 'str' object does not support item assignment
```

`invoice_no[0]` reads a character. It cannot be the target of an assignment because a `str` object does not support item assignment.

## 3. Understanding the error

When immutability causes an error, change the update plan. Do not assign directly inside the original string.

```python
customer_code = "C-1023"

try:
    customer_code[0] = "S"
except TypeError as error:
    print(type(error).__name__)
    print(error)
```

**Output**

```text
TypeError
'str' object does not support item assignment
```

`try` and `except` are used here only to display the error. Full exception handling comes in Chapter 12. The main point is that string item assignment is not allowed.

## 4. Building a new string

We can build a new string and assign it to the same or another variable. The old string object is not changed.

```python
customer_name = "Rahim Traders"

updated_name = "Mr. " + customer_name

print(customer_name)
print(updated_name)
```

**Output**

```text
Rahim Traders
Mr. Rahim Traders
```

`customer_name` keeps the original value. `updated_name` is a new string. The `+` operator joins the two strings.

## 5. Using concatenation

Concatenation means joining strings. The `+` operator creates a new string.

```python
prefix = "INV"
year = "2024"
serial = "007"

invoice_no = prefix + "-" + year + "-" + serial
print(invoice_no)
```

**Output**

```text
INV-2024-007
```

Each part was stored separately. Concatenation joined the parts with hyphens into a new invoice code.

A string and a number cannot be joined directly with `+`. Here, every part is already a string.

## 6. Replacing middle text with slicing

To replace a character or section, slice the text before and after it. Put the new text between those slices.

```python
invoice_no = "INV-2024-007"

updated_invoice = invoice_no[:4] + "2025" + invoice_no[8:]

print(invoice_no)
print(updated_invoice)
```

**Output**

```text
INV-2024-007
INV-2025-007
```

`invoice_no[:4]` keeps the prefix and first hyphen. `invoice_no[8:]` keeps the second hyphen and serial. The new year creates a new invoice string.

This is not direct assignment. It builds a new string from three parts.

## 7. Safe updates with `replace()`

Use `replace()` when the text to change is known. It does not change the original string. It returns a new string.

```python
invoice_no = "INV-2024-007"
updated_invoice = invoice_no.replace("2024", "2025")

print(invoice_no)
print(updated_invoice)
```

**Output**

```text
INV-2024-007
INV-2025-007
```

The original invoice stays the same. `updated_invoice` contains the new year. This is more readable than counting slice boundaries when the target text is known.

`replace()` can change every matching part. Choose the target carefully in business data.

## 8. Updating with `split()` and `join()`

We can split an invoice into a list, change one item, and join the list again. This makes the parts visible.

```python
invoice_no = "INV-2024-007"
parts = invoice_no.split("-")
parts[1] = "2025"
updated_invoice = "-".join(parts)

print(parts)
print(updated_invoice)
```

**Output**

```text
['INV', '2025', '007']
INV-2025-007
```

The string is immutable, but `parts` is a list. A list item can be updated. `join()` then creates a new string.

The original `invoice_no` is still unchanged.

## 9. Keeping original and updated values

Keeping both values helps with audit and comparison in business reports.

```python
raw_invoice = " inv/2024/007 "

clean_invoice = raw_invoice.strip().upper().replace("/", "-")

print(f"Original: {raw_invoice}")
print(f"Cleaned: {clean_invoice}")
```

**Output**

```text
Original:  inv/2024/007 
Cleaned: INV-2024-007
```

The original input is kept for an audit trail. The cleaned value is prepared for the report. Creating a new value follows the immutability rule.

## 10. A business code correction workflow

We cannot directly change the prefix of a customer code. We can slice the old code and build a new one.

```python
customer_code = "C-1023"

supplier_code = "S" + customer_code[1:]

print(customer_code)
print(supplier_code)
```

**Output**

```text
C-1023
S-1023
```

`customer_code[1:]` keeps the hyphen and number. Adding `"S"` creates a new supplier code. The original customer code remains unchanged.

## Synthesis table

| Task | Wrong idea | Safe pattern | Result |
|---|---|---|---|
| Change first character | `text[0] = "X"` | `"X" + text[1:]` | New string |
| Change middle text | Direct assignment | `text[:start] + new + text[stop:]` | New string |
| Change known text | Character assignment | `text.replace(old, new)` | New string |
| Change separated parts | Update a string item | Split, update, then `join()` | New string |
| Keep original | Overwrite only | Keep `old_text` and `new_text` | Audit-friendly |
| Read a string | `text[index]` | Same syntax | Character result |

## Troubleshooting

### Problem 1: A `TypeError` appears

- What is happening: the learner tries `text[0] = "X"`.
- Most likely cause: strings are immutable.
- Step-by-step fix: slice the old parts, add the new part, or use `replace()`.
- Prevention: never use direct item assignment on a string.

### Problem 2: The original value did not change

- What is happening: the updated value is visible, but the original variable still has the old text.
- Most likely cause: Python returned a new string without changing the original object.
- Step-by-step fix: store the result in a new variable, or write `text = text.replace(...)` when appropriate.
- Prevention: give original and updated values separate purposes.

### Problem 3: A character disappeared during a slicing update

- What is happening: the new string is missing part of the prefix or suffix.
- Most likely cause: a wrong slice boundary, especially forgetting that stop is excluded.
- Step-by-step fix: print the prefix and suffix separately, then join the new part.
- Prevention: write down which character belongs before and after the boundary.

### Problem 4: The split and join format is wrong

- What is happening: the invoice has too few or too many hyphens.
- Most likely cause: different split and join separators, or an empty list item.
- Step-by-step fix: print the parts list, inspect its items, then join with the correct separator.
- Prevention: check the code format before and after the update.

## Common Misconceptions

1. **Wrong:** an immutable variable cannot receive a new value -> **Truth:** a variable can be assigned a new string.
2. **Wrong:** `text[0]` can replace a character -> **Truth:** it only reads a character.
3. **Wrong:** `replace()` changes the original string inside itself -> **Truth:** it returns a new string.
4. **Wrong:** `split()` turns the original string into a list -> **Truth:** it creates a separate list result.
5. **Wrong:** assigning a new string to the same variable changes the old object -> **Truth:** the variable points to a new object.

## Quiz

### 1. What does string immutability mean?

a. String characters cannot be updated directly  
b. Strings cannot be printed  
c. String variables cannot exist

**Answer: a.** A string does not support item assignment.

### 2. What happens with `text[0] = "X"`?

a. The first character changes  
b. A `TypeError` occurs  
c. The value becomes `None`

**Answer: b.** String item assignment is not allowed.

### 3. Which one correctly creates a new string?

a. `text[0] = "X"`  
b. `text.replace("A", "B")`  
c. `text[0] == "X"`

**Answer: b.** `replace()` returns a new string.

### 4. How can `"C-1023"` become `S-1023`?

a. `"S" + code[1:]`  
b. `code[0] = "S"`  
c. `code.replace(0, "S")`

**Answer: a.** A new prefix is joined to a slice.

### 5. What can change after `parts = text.split("-")`?

a. An item in `parts`  
b. The original string character directly  
c. The immutable part of the string

**Answer: a.** `parts` is a list, so its item can change.

### 6. What does `replace()` usually return?

a. A new string  
b. A list  
c. An index

**Answer: a.** It returns a new string without changing the original.

### 7. What does `invoice_no[:4] + "2025" + invoice_no[8:]` do?

a. Deletes the invoice  
b. Builds a new invoice with a new year  
c. Only searches for the year

**Answer: b.** It joins the prefix, new year and suffix.

## Key Idea

Strings are immutable, so we cannot assign directly to a character or slice. Use slicing, concatenation, `replace()`, or `split()` and `join()` to build a new string. Keeping original and updated values separate supports business audits.

**Rhyme 1:** Strings do not break, they take a new design,  
**Rhyme 2:** Slice and join the pieces, let clean code shine.
