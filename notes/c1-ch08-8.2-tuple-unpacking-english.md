## 6. Basic tuple unpacking

Three tuple values can move into three variables.

```python
invoice = ("INV-2024-007", "Rahim Traders", 50000)
invoice_no, customer, amount = invoice

print(invoice_no)
print(customer)
print(amount)
```

**Output**

```text
INV-2024-007
Rahim Traders
50000
```

- The first value goes to `invoice_no`.
- The second goes to `customer`.
- The third goes to `amount`.

## 7. Unpacking and position

Unpacking gives record fields clear names.

```python
customer_record = ("Karim Store", 32000, "Active")
name, balance, status = customer_record

print(f"{name}: {balance}, {status}")
```

**Output**

```text
Karim Store: 32000, Active
```

The variable order must match the tuple order.

## 8. A count mismatch

The value and variable counts must match.

```python
record = ("Rahim Traders", 50000, "Review")
name, balance = record
```

**Output**

```text
ValueError: too many values to unpack (expected 2)
```

Use three variables, or use star unpacking.

## 9. Star unpacking

One variable can receive several remaining values.

```python
sales = ("Rahim Traders", 12000, 9500, 8800, 13200)
customer, *daily_sales = sales

print(customer)
print(daily_sales)
```

**Output**

```text
Rahim Traders
[12000, 9500, 8800, 13200]
```

`*daily_sales` receives the remaining values as a list.

## 10. Tuple versus list

```python
approved_period = ("January", "Approved")
daily_report = ["Monday", "Tuesday"]

print(type(approved_period).__name__)
print(type(daily_report).__name__)
```

**Output**

```text
tuple
list
```

An approved fixed pair suits a tuple. A daily report that grows suits a list.

## 11. The business choice

```python
invoice_fields = ("INV-2024-007", "Rahim Traders", 50000)
invoice_no, customer, amount = invoice_fields

daily_sales = [12000, 9500, 8800]
daily_sales.append(13200)

print(invoice_no, customer, amount)
print(daily_sales)
```

**Output**

```text
INV-2024-007 Rahim Traders 50000
[12000, 9500, 8800, 13200]
```

The fixed invoice identity uses a tuple. The changing daily figures use a list.

## 12. A decision rule

Use a tuple when values and count should stay fixed. Use a list when items will be added, removed, or changed. Choosing a structure is part of business meaning.

| Need | Good choice |
|---|---|

## 14. Troubleshooting

### Problem 1: `ValueError: too many values to unpack`
- **What happens:** The tuple has more values than variables.
- **Likely cause:** A new record field was added.
- **Fix:** Add a variable or use star unpacking.
- **Prevent it:** Record the expected field count.

### Problem 2: `ValueError: not enough values to unpack`
- **What happens:** There are more variables than values.
- **Likely cause:** The record shape was misunderstood.
- **Fix:** Reduce variables or inspect the source record.
- **Prevent it:** Print a sample tuple first.

### Problem 3: Fields reach the wrong variables
- **What happens:** The code runs, but the report is wrong.
- **Likely cause:** Variable order does not match tuple order.
- **Fix:** Arrange variables by tuple position.
- **Prevent it:** Write the field names before unpacking.

### Problem 4: A tuple rejects `append()`
- **What happens:** An `AttributeError` appears.
- **Likely cause:** A list method was used on a tuple.
- **Fix:** Use a list when the data must change.
- **Prevent it:** Separate fixed records from changing collections.

## 15. Common Misconceptions

1. **Wrong:** Unpacking destroys the tuple. → **Truth:** The source tuple remains.
2. **Wrong:** Variable order does not matter. → **Truth:** Wrong order gives wrong fields.
3. **Wrong:** Star unpacking stores a tuple. → **Truth:** The star target receives a list.
4. **Wrong:** A tuple is always better than a list. → **Truth:** Lists suit changing data.
5. **Wrong:** Unpacking works only with tuples. → **Truth:** Compatible iterable data can also unpack.

### Exercise 5: Sreepati debugging bug

Sreepati unpacked a three-field customer record into two variables.

```python
record = ("Rahim Traders", 50000, "Review")
customer, balance = record
print(customer, balance)
```

**Wrong output**

```text
ValueError: too many values to unpack (expected 2)
```

The boss asked, “Where will you keep the review status?”

**Diagnosis:** There are three values but only two variables.

**Minimal fix**

```python
record = ("Rahim Traders", 50000, "Review")
customer, balance, status = record
print(customer, balance, status)
```

**Correct output**

```text
Rahim Traders 50000 Review
```

**Lesson:** Match the variable count to the value count.

## 17. Quiz

1. What does tuple unpacking do?  
   a) Puts values into variables  
   b) Sorts the tuple  
   c) Deletes the tuple  
   **Answer: a.** Each value receives a name.

2. In `a, b = (10, 20)`, what is `b`?  
   a) 10  
   b) 20  
   c) 2  
   **Answer: b.** The second value reaches the second variable.

3. What can a count mismatch cause?  
   a) `ValueError`  
   b) The tuple becomes a list  
   c) It always succeeds  
   **Answer: a.** Counts must match.

4. In `first, *rest = (1, 2, 3)`, what is `rest`?  
   a) 1  
   b) `(2, 3)`  
   c) `[2, 3]`  
   **Answer: c.** A star target receives a list.

5. Which suits a changing daily report?  
   a) tuple  
   b) list  
   c) immutable string  
   **Answer: b.** Lists can be updated.

6. Which suits a fixed approved record?  
   a) tuple  
   b) list alias  
   c) empty variable  
   **Answer: a.** A tuple resists accidental changes.

7. What should unpacking variable order follow?  
   a) Tuple order  
   b) Alphabetical order  
   c) Random order  
   **Answer: a.** Order preserves field meaning.
