## 1. Dirty text কী

Dirty text হলো এমন text যাতে extra spaces, inconsistent capital letters বা ভুল separator থাকে। এটি সবসময় visibly broken নয়, কিন্তু comparison, report এবং lookup-এ সমস্যা তৈরি করতে পারে।

```python
raw_customer = "  rahim TRADERS  "
raw_invoice = " inv/2024/007 "

print(raw_customer)
print(raw_invoice)
```

**Output**

```text
  rahim TRADERS  
 inv/2024/007 
```

Customer name-এর দুই পাশে extra space এবং mixed case আছে। Invoice-এর শুরু ও শেষে space এবং separator হিসেবে slash আছে।

গুরুত্বপূর্ণ line:

- `raw_customer` input-এর original form রাখে।
- `raw_invoice` user-entered invoice reference রাখে।
- `print()` raw data-র সমস্যা চোখে দেখাতে সাহায্য করে।

## 2. Extra spaces চেনা

শুরু বা শেষে extra space report-এ দেখা না গেলেও comparison নষ্ট করতে পারে। `strip()` দিয়ে দুই পাশ পরিষ্কার করা যায়।

```python
raw_name = "  Rahim Traders  "
clean_name = raw_name.strip()

print(raw_name == "Rahim Traders")
print(clean_name == "Rahim Traders")
```

**Output**

```text
False
True
```

Raw value-তে extra space থাকায় প্রথম comparison `False`। `strip()`-এর পরে cleaned value expected name-এর সঙ্গে মিলে গেছে।

`strip()` মাঝের space সরায় না। `Rahim Traders`-এর দুটি word আলাদা রাখাই এখানে দরকার।

## 3. Mixed case standardise করা

একই customer কখনও `Rahim Traders`, কখনও `RAHIM TRADERS`, আবার কখনও `rahim traders` হিসেবে আসতে পারে। Comparison-এর জন্য একটি standard case দরকার।

```python
name_a = "Rahim Traders"
name_b = "RAHIM TRADERS"

key_a = name_a.lower()
key_b = name_b.lower()

print(key_a)
print(key_b)
print(key_a == key_b)
```

**Output**

```text
rahim traders
rahim traders
True
```

দুইটি input-এর display form আলাদা, কিন্তু lowercase comparison key একই। Case standardisation display text বদলানোর সিদ্ধান্ত নয়, এটি matching-এর জন্য একটি নতুন form।

## 4. Stray symbols বোঝা

Stray symbol হলো এমন চিহ্ন যা input format-এ থাকার কথা নয়, অথবা অন্য symbol থাকার কথা। যেমন invoice-এ slash এসেছে, কিন্তু business standard-এ hyphen দরকার।

```python
raw_invoice = "INV/2024/007"
clean_invoice = raw_invoice.replace("/", "-")

print(raw_invoice)
print(clean_invoice)
```

**Output**

```text
INV/2024/007
INV-2024-007
```

Slash-কে hyphen-এ বদলানো হয়েছে। Original invoice এখনও রাখা আছে। সব symbol মুছে না দিয়ে, পরিচিত ভুল symbol-এর নির্দিষ্ট replacement করা নিরাপদ।

## 5. Customer name cleaning

Customer name cleaning-এ সাধারণত outer spaces সরিয়ে comparison-এর জন্য lowercase key তৈরি করা হয়। Readable display name আলাদা রাখা যায়।

```python
raw_customer = "  RAHIM traders  "

display_name = raw_customer.strip()
customer_key = display_name.lower()

print(display_name)
print(customer_key)
```

**Output**

```text
RAHIM traders
rahim traders
```

`display_name` outer spaces ছাড়া original case ধরে রেখেছে। `customer_key` matching-এর জন্য lowercase হয়েছে। একই data-র display form এবং comparison form আলাদা কাজ করে।

যদি report-এ সব নাম একই case-এ দরকার হয়, `display_name = raw_customer.strip().title()` ব্যবহার করা যায়, কিন্তু `title()` আজকের মূল method নয়। আজ আমরা পরিচিত methods দিয়েই workflow বানাচ্ছি।

## 6. Invoice code cleaning

Invoice cleaning-এ outer spaces, mixed case এবং known separator একসঙ্গে ঠিক করা যায়।

```python
raw_invoice = " inv/2024/007 "

clean_invoice = raw_invoice.strip().upper().replace("/", "-")

print(clean_invoice)
print(clean_invoice.startswith("INV-"))
print(clean_invoice.endswith("007"))
```

**Output**

```text
INV-2024-007
True
True
```

Cleaning order:

- `strip()` দুই পাশের space সরিয়েছে।
- `upper()` letters standard করেছে।
- `replace("/", "-")` separator standard করেছে।
- `startswith()` ও `endswith()` final result যাচাই করেছে।

## 7. Cleaning order

একাধিক সমস্যা থাকলে method-এর ক্রম result-এ প্রভাব ফেলতে পারে। সাধারণত আগে outer whitespace, তারপর case, তারপর known symbols ঠিক করা সহজ।

```python
raw_code = "  inv/2024/007  "

step_1 = raw_code.strip()
step_2 = step_1.upper()
step_3 = step_2.replace("/", "-")

print(step_1)
print(step_2)
print(step_3)
```

**Output**

```text
inv/2024/007
INV/2024/007
INV-2024-007
```

প্রতিটি step আলাদা variable-এ রাখা হয়েছে। এতে debugging সহজ হয় এবং কোন method কী পরিবর্তন করেছে তা দেখা যায়।

এক লাইনে একই workflow লেখা যায়:

```python
clean_code = raw_code.strip().upper().replace("/", "-")
print(clean_code)
```

**Output**

```text
INV-2024-007
```

## 8. Original ও cleaned value রাখা

Business data cleaning-এ raw input হারানো উচিত নয়। Audit বা ভুল খোঁজার সময় original value দরকার হতে পারে।

```python
raw_name = "  Karim STORE  "
clean_name = raw_name.strip().lower()

print(f"Raw: {raw_name}")
print(f"Clean key: {clean_name}")
```

**Output**

```text
Raw:   Karim STORE  
Clean key: karim store
```

`raw_name` user input হিসেবে রাখা হয়েছে। `clean_name` matching-এর জন্য তৈরি হয়েছে। দুইটি variable-এ দুইটি উদ্দেশ্য পরিষ্কার থাকে।

## 9. Cleaning result যাচাই

Cleaning শেষ হয়েছে মনে করলেই হবে না। Expected prefix, suffix বা separator count দিয়ে result check করা দরকার।

```python
raw_invoice = " inv/2024/007 "
clean_invoice = raw_invoice.strip().upper().replace("/", "-")

print(clean_invoice.count("/"))
print(clean_invoice.count("-"))
print(clean_invoice.startswith("INV-"))
```

**Output**

```text
0
2
True
```

Cleaned invoice-এ slash নেই, hyphen দুইটি এবং expected prefix আছে। এই checks business rule-এর simple evidence দেয়।

`True` পাওয়া মানে এই checks pass করেছে, code-এর সব possible problem শেষ হয়েছে এমন নয়।

## 10. Safe business cleaning workflow

একটি customer field এবং invoice field আলাদা rule-এ clean করা যায়। Customer-এর internal space রাখা হবে, invoice-এর known slash বদলানো হবে।

```python
raw_customer = "  rahim TRADERS  "
raw_invoice = " inv/2024/007 "

customer_key = raw_customer.strip().lower()
clean_invoice = raw_invoice.strip().upper().replace("/", "-")

print(f"Customer key: {customer_key}")
print(f"Invoice: {clean_invoice}")
print(clean_invoice.startswith("INV-"))
print(clean_invoice.endswith("007"))
```

**Output**

```text
Customer key: rahim traders
Invoice: INV-2024-007
True
True
```

এখানে customer-এর মাঝের space রাখা হয়েছে। Invoice-এর slash বদলে hyphen করা হয়েছে। একই cleaning rule সব field-এ অন্ধভাবে প্রয়োগ না করে field-এর business meaning অনুযায়ী rule বেছে নেওয়া হয়েছে।

## Synthesis table

| Mixed case | `lower()` | `"RAHIM".lower()` | `rahim` |
| Report display case | `upper()` | `"inv".upper()` | `INV` |
| Known wrong symbol | `replace()` | `"INV/1".replace("/", "-")` | `INV-1` |

## Troubleshooting

### Problem 1: Cleaning-এর পরও name match করছে না

- কী হচ্ছে: একই customer মনে হলেও comparison `False`।
- সম্ভাব্য কারণ: outer space বা mixed case রয়ে গেছে।
- ধাপ: দুই input-এ `strip().lower()` প্রয়োগ করুন, তারপর key compare করুন।
- প্রতিরোধ: display value এবং comparison key আলাদা standard form-এ রাখুন।

### Problem 2: Invoice-এর দরকারি separator মুছে গেছে

- কী হচ্ছে: cleaned code আর readable বা valid নয়।
- সম্ভাব্য কারণ: সব symbol বা সব space অন্ধভাবে remove করা হয়েছে।
- ধাপ: raw format দেখুন, শুধু পরিচিত wrong symbol replace করুন, তারপর prefix ও suffix check করুন।
- প্রতিরোধ: প্রতিটি symbol-এর business meaning আগে বুঝুন।

### Problem 3: Cleaning order-এ result ভুল হচ্ছে

- কী হচ্ছে: method চালানোর পরে expected standard form আসছে না।
- সম্ভাব্য কারণ: case, whitespace এবং separator rules এলোমেলো ক্রমে প্রয়োগ হয়েছে।
- ধাপ: `strip()`, case conversion এবং known replacement আলাদা step-এ print করুন।
- প্রতিরোধ: ধাপের নামসহ intermediate variables ব্যবহার করুন।

### Problem 4: Raw data হারিয়ে গেছে

- কী হচ্ছে: পরে বোঝা যাচ্ছে না user কী input দিয়েছিল।
- সম্ভাব্য কারণ: raw variable-এর উপর cleaned result assign করা হয়েছে।
- ধাপ: raw value আলাদা variable-এ রাখুন এবং cleaned value নতুন variable-এ তৈরি করুন।
- প্রতিরোধ: audit দরকার হলে কখনও raw input overwrite করবেন না।

## Common Misconceptions

1. **ভুল:** সব dirty text-এ সব spaces মুছে ফেলতে হবে → **সত্য:** internal space-এর business meaning থাকতে পারে।
2. **ভুল:** uppercase করলেই customer data clean → **সত্য:** whitespace এবং stray symbols-ও আলাদা করে ঠিক করতে হয়।
3. **ভুল:** `replace("/", "")` সব invoice-এর জন্য নিরাপদ → **সত্য:** separator মুছে গেলে code structure নষ্ট হতে পারে।
4. **ভুল:** cleaned result pass করলে raw value আর দরকার নেই → **সত্য:** audit ও debugging-এর জন্য raw value useful।
5. **ভুল:** একই cleaning rule সব field-এ প্রয়োগ করা যায় → **সত্য:** customer name ও invoice code-এর rule আলাদা হতে পারে।

## Key Idea

Dirty text cleaning হলো raw input বুঝে ধাপে ধাপে standard form তৈরি করা। `strip()` outer space, `lower()` বা `upper()` case, এবং `replace()` পরিচিত stray symbol ঠিক করে। Raw ও cleaned value আলাদা রাখলে business audit নিরাপদ থাকে।

**ছড়া ১:** space সরাও, case সাজাও, symbol দাও মান,  
**ছড়া ২:** raw রেখে clean করো, audit থাকে প্রাণ।
