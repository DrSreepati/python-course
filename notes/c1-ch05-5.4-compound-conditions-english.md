## 5. What is a compound condition?

A compound condition contains several comparisons. At the Dhaka wholesale shop, a discount may need both a large order and a safe balance.

```python
order_amount = 12000
customer_balance = 32000

if order_amount >= 10000 and customer_balance >= 30000:
    print("Discount review approved")
else:
    print("Discount review held")
```

**Output**

```text
Discount review approved
```

Both comparisons are true. Therefore, the approval block runs. One false comparison would run `else`.

## 6. `and`: all conditions must be true

`and` means that every required condition must pass. It can shorten a nested if rule.

```python
order_amount = 10000
customer_balance = 30000
profit = 2500

if order_amount >= 10000 and customer_balance >= 30000 and profit > 0:
    print("Approve profitable credit order")
else:
    print("Review order")
```

**Output**

```text
Approve profitable credit order
```

All three comparisons are true. The exact boundaries 10000 and 30000 are accepted.

## 7. `or`: at least one condition

Sometimes either of two reasons can create priority.

```python
customer_name = "Karim Store"
outstanding = 32000
order_amount = 8000

if outstanding >= 30000 or order_amount >= 15000:
    priority = "Manager review"
else:
    priority = "Normal review"

print(f"{customer_name}: {priority}")
```

**Output**

```text
Karim Store: Manager review
```

The outstanding balance passes. The order does not. `or` still makes the full condition true.

## 8. `not`: reverse a result

`not` changes true to false, and false to true. A well-named Boolean variable makes this clear.

```python
payment_received = False

if not payment_received:
    print("Payment follow-up required")
else:
    print("Payment received")
```

**Output**

```text
Payment follow-up required
```

The variable is false. `not` makes the tested result true, so follow-up is required.

## 9. Parentheses and mixed rules

Parentheses show the intended grouping when `and` and `or` appear together.

```python
order_amount = 12000
customer_balance = 32000
urgent_request = False

if (order_amount >= 10000 and customer_balance >= 30000) or urgent_request:
    print("Send to manager")
else:
    print("Keep in normal queue")
```

**Output**

```text
Send to manager
```

The grouped left side is true. `urgent_request` is false, but `or` keeps the full rule true.

## 10. Compound business classifications

Compound rules can classify overdue and payment status.

```python
customer_name = "Rahim Traders"
outstanding = 50000
days_overdue = 12
payment_received = False

if outstanding > 0 and days_overdue > 0 and not payment_received:
    status = "Overdue follow-up"
elif outstanding == 0 or payment_received:
    status = "Clear"
else:
    status = "Review account"

print(f"{customer_name}: {status}")
```

**Output**

```text
Rahim Traders: Overdue follow-up
```

Outstanding and overdue are positive. Payment has not arrived. Therefore, follow-up is selected.

## 11. Boundary testing

Test every threshold below, at, and above its boundary.

```python
order_amount = 9999
balance = 30000

if order_amount >= 10000 and balance >= 30000:
    print("Eligible")
else:
    print("Not eligible")
```

**Output**

```text
Not eligible
```

The balance passes. The order is 9999. One false part makes the `and` rule false.

## 12. Readability and rule names

Give long conditions meaningful names. This helps business reviews.

```python
order_amount = 13200
customer_balance = 71000
payment_received = True

large_order = order_amount >= 10000
safe_balance = customer_balance >= 30000
paid = payment_received

if large_order and safe_balance and paid:
    print("Release order")
else:
    print("Hold order")
```

**Output**

```text
Release order
```

The named Boolean values make the final decision readable. The rule shows business meaning, not raw numbers.

## 13. Synthesis table

| Business meaning | Python tool |
|---|---|
| Require every condition | `and` |
| Accept an alternative | `or` |
| Require a condition to be false | `not` |
| Clarify mixed rules | parentheses |
| Explain a long rule | named Boolean variables |

## 14. Troubleshooting

### Problem 1
- What happens: a valid order is rejected.
- Likely cause: one `and` comparison is false.
- Fix: inspect each comparison separately.
- Prevention: test below, at, and above each boundary.

### Problem 2
- What happens: either balance or order alone does not grant approval.
- Likely cause: `and` was used for an alternative rule.
- Fix: use `or` when one reason is enough.
- Prevention: write “all” or “any” before coding.

### Problem 3
- What happens: an urgent request still enters the normal queue.
- Likely cause: mixed grouping was misunderstood.
- Fix: put the intended group inside parentheses.
- Prevention: always use parentheses with mixed `and` and `or`.

### Problem 4
- What happens: a received payment still gets a follow-up message.
- Likely cause: `not payment_received` was grouped incorrectly.
- Fix: inspect the Boolean value and the exact expression tested.
- Prevention: use positive names such as `payment_received`.

## 15. Common Misconceptions

1. **Wrong:** `and` means any one condition → **Truth:** every condition must be true.
2. **Wrong:** `or` requires both conditions → **Truth:** one true alternative is enough.
3. **Wrong:** `not` changes the variable → **Truth:** it reverses the tested result.
4. **Wrong:** parentheses are only decoration → **Truth:** they show rule grouping.
5. **Wrong:** named Booleans are unnecessary → **Truth:** they help audits and debugging.

## 17. Quiz

1. What does `and` require?  
   a) all conditions true  b) one false  c) no comparison  
   **Answer: a**, because every required condition must pass.
2. When is `or` true?  
   a) when all are false  b) when at least one is true  c) never  
   **Answer: b**, because one valid alternative is enough.
3. What is `not True`?  
   a) True  b) None  c) False  
   **Answer: c**, because `not` reverses the result.
4. What helps when `and` and `or` are mixed?  
   a) parentheses  b) input  c) slicing  
   **Answer: a**, because grouping becomes clear.
5. Is `9999 >= 10000` true?  
   a) True  b) False  c) 10000  
   **Answer: b**, because 9999 is smaller.
6. What happens when one part of an `and` rule is false?  
   a) True  b) False  c) a string  
   **Answer: b**, because every part must be true.
7. Why use a named Boolean?  
   a) to show the rule meaning  b) to make a loop  c) to increase a number  
   **Answer: a**, because the variable explains the business rule.

## 18. Key Idea

`and` requires all conditions, `or` accepts alternatives, and `not` reverses a result. Parentheses and named Booleans make compound business rules easier to read and audit.

**Rhyme:**  
When every door is open, `and` lets the order go,  
One path is enough for `or`, while `not` turns the flow.
